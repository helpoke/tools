一、格式不兼容是最被低估的效率杀手

  • iPhone 拍的 MOV 视频在 Windows 上打不开、客户发来的 AVI 文件无法嵌入网页、录制的 WebM 素材在剪辑软件里无法导入——格式不兼容的问题每天都在发生。安装格式转换软件？体积大、操作复杂、还要担心编解码器缺失。本工具基于 FFmpeg WASM 在浏览器中完成格式转换，支持 MP4、WebM（VP9/VP8）、TS 等格式的互相转换。
  • 转换过程中可以精细控制编码参数：视频码率、音频码率、分辨率、帧率、是否保留音频——所有参数都可自定义。也可以选择"高质量/中质量/低质量"预设快速转换，不需要理解编码细节。
  • 实时进度显示——转换过程中可以看到当前进度、已用时间和预估剩余时间。转换完成后显示输出文件信息（格式、分辨率、大小），支持一键下载。所有处理在浏览器本地完成，视频不上传到任何服务器。

二、输出格式的技术特性

  • MP4（H.264 + AAC）：兼容性之王——所有浏览器、操作系统、手机、电视、播放器都支持。如果目标是在尽可能多的设备上播放，MP4 是唯一选择。H.264 编码效率适中，文件体积合理。
  • WebM VP9：Google 主导的开源格式，压缩效率比 H.264 高 20%-30%——同等画质下文件更小。Chrome、Firefox、Edge 原生支持，但 Safari（尤其是 iOS）支持有限。适合网页嵌入和开源生态。
  • WebM VP8：VP9 的前代版本，兼容性略好于 VP9（旧版浏览器也支持），但压缩效率低 10%-15%。如果需要 WebM 格式且要兼容更多浏览器，选 VP8。
  • MPEG-TS（.ts）：流媒体传输格式，常用于 HLS 直播流。普通用户很少需要 TS 格式——它主要用于视频流服务的后端处理。如果你不确定是否需要 TS，大概率你不需要。

三、转换参数的影响

  • 视频码率：直接决定输出文件大小。码率越高画质越好但文件越大。建议值：720p 用 2000-3000kbps，1080p 用 4000-6000kbps，4K 用 15000-25000kbps。
  • 音频码率：音频码率影响声音质量。128kbps 是音乐的可接受质量，192kbps 是高质量，320kbps 是 CD 级。对于语音类视频，96kbps 已经足够。
  • 分辨率缩放：转换时可以同时调整分辨率——原始 1080p 视频转为 720p 输出，文件体积减少 50%+。支持原始、75%、50%、25% 和自定义宽度。
  • 帧率控制：保持原始帧率或指定帧率。降低帧率可以减少数据量但影响流畅度。建议保持原始帧率，除非明确需要降低。

格式转换操作步骤

载入视频

  • 上传方式：点击或拖拽上传，支持所有主流视频格式（MP4/WebM/MOV/AVI/MKV/FLV/OGV 等）。
  • 格式检测：上传后工具自动识别视频的编码格式、分辨率、帧率、时长等信息，显示在视频下方。
  • 文件大小：建议单个视频不超过 1GB。超大视频的处理时间较长，但工具本身没有文件大小限制。
  • 预览播放：上传后可以在页面上直接预览视频内容，确认上传的是正确的文件。

选择输出格式

  • MP4（H.264）：兼容性最好，适合需要在各种设备上播放的场景。
  • WebM VP9：压缩效率最高，适合网页嵌入和现代浏览器场景。
  • WebM VP8：兼容性较好的 WebM 版本，适合需要广泛 WebM 支持的场景。
  • 自定义参数：除格式外，还可以调整视频码率、音频码率、分辨率和帧率。不确定参数时选择"高质量"预设。

设置编码参数

  • 质量预设：高/中/低三档预设，自动设置合理的码率值。也可以选择"自定义"手动输入码率。
  • 分辨率：保持原始或按比例缩放。降低分辨率是减小文件体积的有效手段。
  • 自定义宽度：输入目标宽度（像素），高度自动按比例计算。适合需要特定尺寸的场景。

五、不同场景的推荐设置

  • 社交媒体分享：MP4 + 720p + 中质量。文件通常在 20-50MB，画质在手机屏幕上足够好。
  • 网页嵌入：WebM VP9 + 720p + 中质量。文件最小，现代浏览器播放流畅。
  • Apple 设备：MP4（H.264 + AAC）。Apple 设备对 H.264 支持最好，HEVC 也可以但兼容性略差。
  • 最大兼容性：MP4 + H.264 + 原始分辨率 + 高质量。文件较大但确保在任何设备上都能播放。

六、典型应用场景

  • 跨平台分享：收到 MOV 格式视频需要发给 Windows 用户？转为 MP4 即可。网页上的 WebM 需要在 Safari 播放？转为 MP4。
  • 网页视频嵌入：将大体积的 MP4 转为 WebM VP9，文件减小 25%+，网页加载更快。
  • 设备适配：不同设备偏好的格式不同——Android 优先 WebM，iOS 优先 MP4，Linux 两者都支持。
  • 格式转换 + 压缩：转换格式的同时调整码率和分辨率，一举两得——既解决了兼容性问题，又优化了文件大小。

注意事项

数据安全

  • 本地处理：基于 FFmpeg WASM，视频数据完全在浏览器中处理，不上传到任何服务器。
  • 内存管理：转换完成后自动释放内存。处理大文件时建议关闭不必要的浏览器标签页。
  • 临时数据：关闭页面后所有处理数据自动清除，不留下任何缓存。

性能说明

  • 处理时间：取决于视频时长、分辨率和编码复杂度。5 分钟 1080p 视频转 MP4 约 2-5 分钟，转 WebM VP9 约 5-10 分钟（VP9 编码更复杂）。
  • CPU 占用：视频编码是 CPU 密集型任务，处理时 CPU 占用可能达到 80%-100%。这是正常的——编码完成后自动释放。
  • 内存需求：建议至少 4GB 可用内存。处理 4K 视频时可能需要 2GB+ 内存。

格式限制说明

  • 不支持的编码：部分专业编码格式（如 ProRes、DNxHD）可能不被 FFmpeg WASM 支持。遇到无法处理的格式时会显示错误提示。
  • DRM 保护：带有 DRM 保护的视频（如 Netflix 下载的影片）无法转换——这是版权保护机制，工具无法绕过。
  • 多音轨/字幕：转换时只处理第一个视频轨道和第一个音频轨道。多音轨或内嵌字幕的视频会丢失额外的轨道。

画质保障

  • 转码损失：从有损格式（如 MP4 H.264）转到另一种有损格式（如 WebM VP9），会有"二次编码损失"。画质可能略有下降——选择高质量参数可以最小化影响。
  • 无损转换不存在：除了同格式同参数的"复制"模式（本工具不支持），任何转码都会引入一定程度的质量损失。但高质量参数下的损失肉眼通常不可见。
  • 音频质量：音频同样经历重新编码。如果原始音频质量很高（如 320kbps MP3），转为低码率（如 96kbps）会有明显的音质损失。

常见问题

  • Q: 转换后没有声音？A: 可能原始视频没有音频轨道，或选择的输出格式不支持原始音频编码。尝试勾选"保留音频"或更换输出格式。
  • Q: 为什么转换后文件反而更大？A: 如果输出码率高于原始码率，文件会变大。转码不会"恢复"已丢失的信息——高码率只是浪费了空间。建议输出码率不超过原始码率。
  • Q: 能批量转换多个视频吗？A: 当前版本一次只能转换一个视频。转换完成后再上传下一个。
  • Q: 转换过程中可以暂停吗？A: 不支持暂停。如果中断需要重新开始。建议在网络稳定、不关闭页面的情况下进行转换。
