工具介绍

树在数据库里从来就不是一棵树

  • 菜单表、部门表、分类目录、评论区，落到关系型数据库里都是一张带 parent_id 的平铺表；接口返回的也往往是扁平数组，前端渲染时才发现需要 children 嵌套。手写这段装配逻辑不难，难的是它边界上一堆坑：父找不到时整棵子树静默消失、数据里混进一条自环把页面卡死、两个节点互相引用造成无限递归。
  • 线上事故最常见的形态是"菜单少了一半且不报错"：某次批量导入把 parentId 写成了一个不存在的值，这批节点连同它们的子孙全部成了孤儿，而装配代码只用 filter 挑根节点，既不告警也不留痕。本工具把这类结构缺陷当场列出：哪一行、哪个 id、父指向谁、子孙共多少个。
  • 反向需求同样频繁：后台按层级渲染好的树，导出给只认平铺表的结构、或喂给单元测试的 fixture，需要拍平成带父指针的数组并保证不丢节点。这里是一个双向工具，而不是两个各写一遍的脚本。

核心功能

  • 双向装配与拍平：扁平数组按父子关系一次建树（O(n) 哈希索引，不做嵌套遍历），树则深度优先拍平成数组；字段名（ID 字段、父级字段、子节点字段）全部可改，直接对上您现有的接口命名。
  • 四类结构问题全覆盖：重复 id、父指向自己的自环、A→B→A 的父子环、父不存在的孤儿，逐条进入问题清单并给出行号与节点标识；环会被打断而非让页面栈溢出，孤儿可按选项提升为根，保证不丢数据。
  • 结果能直接用也能看：输出缩进可选 2 / 4 / 制表符 / 紧凑单行，子节点排序支持原顺序、按 ID、按名称字段、按排序号字段，一键复制或下载 .json 文件，统计条给出节点数、根数、最大深度与问题数。

使用说明

  1. 确认转换方向（默认"扁平数组 → 树"），把接口返回的数组或数据库导出的 JSON 整块粘贴到左侧；JSONL（一行一个对象）与包在对象里的数组也认。
  2. 把 ID 字段、父级字段、子节点字段改成您自己的命名（如 menuId / pid / items），需要时再选排序方式与输出缩进。
  3. 点击"转换"查看结果与统计，右侧问题清单会列出重复 id、环、孤儿的具体行号；修数据时建议取消"孤儿节点提升为根"，让缺父的节点显式暴露在清单里。

注意事项

  • ID 与父级字段的比较按"字符串化后的值"进行，因此数字 1 与字符串 "1" 视为同一个节点；null、undefined、空字符串、0 与 '0' 都按"顶层根节点"处理。若您的数据用 0 表示顶级目录而又确实存在 id 为 0 的节点，请改掉这批 0 值再转，否则会被判成互指环。
  • 建树时不会修改节点的业务字段：除新增子节点数组外，原字段顺序与值都保持不动；勾选"保留父级字段"时嵌套结果里仍带 parentId，取消后输出更贴近前端组件的 props 形状。
  • 检测到父子环时，工具会在成环的边上断开一条使遍历能终止，并在清单里写明被断开的是哪个节点的父指向；这条边上的子孙会作为独立根节点出现在结果末尾，不会静默丢弃。
  • "按名称字段"与"按排序号字段"会在 name / title / label / text 与 sort / order / weight / rank 中取第一个存在的字段；都没有时等同"保持原顺序"，清单不做提示。
  • 单次建议不超过 50000 个节点、输入不超过 10MB；全部解析与转换在浏览器主线程同步完成，期间页面可能短暂停顿。本工具不记录任何输入，关闭页面即清除。

典型场景

  • 后台菜单渲染：接口一次性返回全部菜单项，前端装配成侧边栏需要的多级 children 结构，顺便确认没有节点因父 id 拼错而消失。
  • 组织架构导入：把 Excel 导出的部门表（每行一个部门加"上级部门"列）先拍成 JSON 再建树，一眼看出哪几个部门的上级不存在。
  • 省市区级联：三级联动组件初始化需要嵌套数据，从行政区划平铺表按 parentCode 一次生成，比在 SQL 里自连接快得多。
  • 评论区盖楼：接口按时间序返回带 replyTo 的评论列表，装配成楼层嵌套，同时排查用户连自己评论回复造成的自环。
  • 测试数据准备：把一个真实的嵌套配置拍平成带父指针的数组写进 fixture，或反向用拍平结果核对层级深度是否符合预期。
