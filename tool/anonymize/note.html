什么是数据脱敏工具？

数据脱敏工具是一款免费的在线隐私保护助手。截图里的手机号、日志中的身份证号、要发到群里的客户名单、贴到技术社区的报错信息——直接转发极易泄露隐私。粘贴进来即可自动识别常见敏感字段并一键打码。

工具内置针对中国大陆格式的正则识别引擎，覆盖手机号、固定电话、18/15 位身份证、16-19 位银行卡、电子邮箱、IPv4 地址，并提供掩码、哈希、泛化三种脱敏策略。全部处理在浏览器本地运行，不加载任何第三方处理库，原文不会上传；也可直接上传 .xlsx / .csv / .txt / .tsv / .log 文件载入数据。

三种脱敏方式

  • 掩码打码：保留首尾若干位、中间用 * 替换，如 138****5678，直观表达"已打码"，适合给人阅读。
  • 哈希替身：把原值替换成稳定的短码，同一号码每次得到相同码，便于脱敏后仍能去重、关联统计。
  • 泛化保留：只保留大致范围，如 IP 显示 192.168.*.*、身份证保留前 6 位地区码，隐藏精确值。

如何快速开始？

第一步：粘贴内容

把需要脱敏的文本或 CSV/TSV 数据粘贴到输入框，点击“载入示例”体验，或直接上传 .xlsx / .csv / .txt 等文件自动载入。

第二步：选择类型与方式

勾选要处理的敏感类型，选择掩码/哈希/泛化，并可调整掩码字符与首尾保留位数。

第三步：脱敏并核对

点击"开始脱敏"，右侧生成结果，下方统计各类替换数量；核对无误后复制或下载。

典型应用场景

报障求助：日志里的手机号、身份证、IP 打码后再发到社区，不泄露他人隐私。

名单流转：客户/员工表格跨部门流转前，脱敏身份证与银行卡，保留可读字段。

演示样例：把生产数据脱敏成"看起来真实但不含真实隐私"的培训、演示样例。

日志分析：用哈希把用户 ID 转成稳定替身码，既做关联统计又不暴露身份。

特点与优势

本地处理，绝不上传 六类敏感信息识别 掩码 / 哈希 / 泛化 首尾保留可调 按类型统计数量 文本 / CSV 通吃 支持上传 xlsx/csv/txt 一键复制与下载

注意事项：

  • 识别基于正则模式，重要合规场景请以专业脱敏系统为准，处理后务必人工抽查关键结果。
  • 哈希为 FNV-1a 非密码学短摘要，用于保持关联性，不能视作强匿名；高敏感数据请用掩码。
  • 本工具面向中国大陆常见格式；其他地区号码、脱敏规则可能不被识别。
  • 数据在浏览器本地处理，不会上传服务器，公共设备建议配合无痕模式。

常见问题

问：掩码、哈希、泛化该怎么选？

答：给人看清楚打码了用掩码；要"同值同码"便于关联分析用哈希；只想保留范围/量级用泛化。

问：会不会误伤普通数字？

答：手机号需 1[3-9] 开头 11 位、银行卡为 16-19 位连续数字、身份证 18/15 位，处理顺序为身份证→银行卡→手机号以避免相互吞并。

问：哈希能还原成原值吗？

答：不能直接逆推，但可被字典枚举碰撞，安全性有限。高敏感数据请改用掩码或带密钥/加盐的专业方案。

问：能处理整张 CSV 表格吗？

答：可以。工具把输入当作文本按正则逐类型替换，表格、散文、日志混排都能处理，结果保留原有结构。

问：掩码保留几位是由什么决定的？

答：“首尾保留位数”控制数字类敏感值头尾各保留几位（默认 3，可 0~4），中间用掩码字符替代；邮箱始终保留首字母与完整域名，IP 只保留前两段。若长度不足以保留头尾，会整体以掩码显示。

问：支持直接上传文件吗？

答：支持。除粘贴文本外，可上传 .xlsx（浏览器本地解析取首个工作表）、.csv / .txt / .tsv / .log 自动载入并脱敏，全程本地完成不上传。

脱敏示例：输入→输出

原始内容（含手机号、身份证、邮箱、IP、银行卡、座机）

客户张三，手机 13812345678，身份证 110101199003071234， 邮箱 zhangsan@example.com，登录 IP 192.168.10.55， 银行卡 6222021234567890123，座机 010-88886666。

掩码方式（默认首尾保留 3 位、掩码字符 *）

客户张三，手机 138*****678，身份证 110************234， 邮箱 z***@example.com，登录 IP 192.168.*.*， 银行卡 622*************123，座机 010******666。

统计条显示共脱敏 6 处（手机 1、身份证 1、银行卡 1、座机 1、IP 1、邮箱 1）。

换为哈希 / 泛化时

  • 哈希：每个原值替换为稳定的 # + 8 位十六进制短码（如 #a3f9c210），同值同码，保留关联分析能力。
  • 泛化：数字类只保留前约 1/3 位数体现量级，IP 形如 192.168.*.*，邮箱形如 z***@example.com。

使用最佳实践

  • 先全选再抽查：第一次把所有类型勾上跑一遍，看各类替换数量是否符合预期，再针对性关闭误伤项。
  • 分析场景用哈希：需要脱敏后仍能做去重、关联、分组统计时，哈希方式最合适。
  • 展示场景用掩码：截图、教程、对外文档里，掩码最能直观表达"此处已保护"。
  • 配合 CSV / 统计工具：脱敏后的表格可继续在"CSV 工具箱""数据统计器"中处理与分享。
  • 本地处理：敏感原文全程在浏览器，关闭页面即清除，公共设备建议无痕模式。
