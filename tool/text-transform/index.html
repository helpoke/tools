文本转换：大小写、全半角、编码格式一键切换

一、文本格式问题是最容易被忽视的效率漏洞

  • 用户输入的邮箱地址大小写不统一导致数据库出现重复记录、从 PDF 复制的文字全角半角混杂导致代码报错、JSON 中的中文字符需要转义为 Unicode 编码——这些看似琐碎的格式问题每天都在消耗开发者和运营人员的时间。本工具集成 20+ 种文本转换功能，覆盖大小写转换、全半角转换、Unicode 编码/解码、Base64 编码、URL 编码、HTML 实体编码等常见需求。
  • 粘贴文本后一键转换——不需要写正则、不需要打开代码编辑器、不需要查 ASCII 表。所有转换在浏览器中完成，处理速度取决于文本长度——通常 10 万字以内的转换在 100ms 内完成。
  • 支持链式转换——先转全角，再转大写，再 Base64 编码——每步转换基于上一步的结果。转换结果可以一键复制或直接编辑后继续转换。

三、各转换功能的技术细节

  • 大小写规则：Title Case 将每个单词首字母大写（hello world → Hello World）；Sentence Case 将每句首字母大写（hello world. goodbye → Hello world. Goodbye）；swapCase 将大写变小写、小写变大写。
  • 全半角映射：全角字符的 Unicode 编码 = 半角编码 + 0xFEE0。如全角"A"（U+FF21）= 半角"A"（U+0041）+ 0xFEE0。转换就是在这个数值空间做加减法。
  • Base64 编码：将文本的 UTF-8 字节序列按 6 位一组重新分组，映射到 64 个可打印字符（A-Z, a-z, 0-9, +, /）。编码后体积增加约 33%——适合在 URL、JSON、邮件中传输二进制数据。
  • URL 编码：将非 ASCII 字符和特殊字符转换为 %XX 格式（百分号后跟两位十六进制）。如中文"你好"编码为 %E4%BD%A0%E5%A5%BD——每个中文字符编码为 3 个百分号序列。

二、大小写转换

  • 转大写：将所有英文字母转为大写——如 "hello world" → "HELLO WORLD"。适用于 SQL 关键字、常量定义、强调文本等场景。
  • 转小写：将所有英文字母转为小写——如 "HELLO WORLD" → "hello world"。适用于 URL 路径、邮箱地址、标准化处理等场景。
  • 首字母大写：每个单词的首字母转为大写——如 "hello world" → "Hello World"。适用于人名、地名、标题等场景。以空格和标点作为单词分隔符。
  • 标题格式：遵循英文标题规范——实词首字母大写，虚词（a, an, the, in, on, at, to, for, and, or, but 等）小写。适用于文章标题、书名、报告标题等正式场合。

三、命名格式转换

  • 驼峰命名（camelCase）：第一个单词全小写，后续单词首字母大写，单词之间无分隔符——如 "hello world" → "helloWorld"。Java、JavaScript、Swift 的变量和方法命名标准。
  • 下划线命名（snake_case）：所有字母小写，单词之间用下划线连接——如 "hello world" → "hello_world"。Python、Ruby、Rust 的变量和函数命名标准。也用于数据库字段名。
  • 短横线命名（kebab-case）：所有字母小写，单词之间用短横线连接——如 "hello world" → "hello-world"。CSS 类名、HTML 属性名、URL 路径的标准格式。Web Components 的标签名也使用此格式。

四、空格处理

  • 清理空格：去除文本首尾的空白字符，将中间的连续空白字符合并为单个空格。适用于从 PDF、网页或 OCR 识别结果中复制的不规则文本。
  • 删除所有空格：去除文本中所有空格字符（包括空格、制表符）。适用于将多行文本压缩为单行，或生成无空格的紧凑格式。

一、转换规则说明

  • 大小写转换仅对英文字母（A-Z, a-z）生效——中文字符、数字、标点符号不受影响。"你好Hello世界World" 转大写后为 "你好HELLO世界WORLD"。
  • 命名格式转换会去除非字母数字字符（如标点、特殊符号），并以空格或特殊字符的位置作为单词分界。例如 "user-name" 转驼峰为 "userName"，"first_name" 转短横线为 "first-name"。
  • 标题格式遵循英文标题规范——冠词（a, an, the）、短介词（in, on, at, to, for, by）、连词（and, or, but）在标题中间时小写，在标题开头时大写。实词（名词、动词、形容词、副词）始终首字母大写。
  • 命名格式转换中的"驼峰命名"默认输出小驼峰（camelCase）——首字母小写。如果需要大驼峰（PascalCase），可以先转驼峰后再手动将首字母大写。

二、性能提示

  • 建议单次处理的文本不超过 10 万字符。超大文本的转换可能需要较长时间，特别是命名格式转换涉及正则表达式匹配和替换。
  • 转换操作是即时的——点击按钮后立即显示结果。如果文本特别大（超过 1MB），浏览器可能短暂卡顿，这是正常的计算开销。
  • 频繁转换时建议分段处理。

常见问题

  • Q: 转换后中文变成乱码？A: 检查编码方式——URL 编码应使用 UTF-8（本工具默认）。如果目标系统使用 GBK，需要额外转换。
  • Q: Base64 解码失败？A: 确保输入的是有效的 Base64 字符串——只包含 A-Z, a-z, 0-9, +, /, = 字符。
  • Q: 能批量转换多个文件吗？A: 当前版本只能处理文本框中的内容。如需处理文件，先将文件内容复制粘贴到输入框。
  • 内存不足：减少文本内容或分段处理。
