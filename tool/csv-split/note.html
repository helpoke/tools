CSV 拆分与合并 - 使用说明与 FAQ

把大 CSV 按行数、按体积、按列取值切成能各自打开的小文件，也能把多份分表合成一张总表；切法讲口径，合并吞数据的事一件都不做

这个工具在做什么？

它做两件互为反向的事。拆分：在一份 CSV / TSV 的记录边界上找切口，按固定行数、按每片体积上限、或按某一列的取值，把它切成若干个可独立打开的小文件，逐个下载或打包成一个 ZIP。合并：把多份分表（列顺序不完全一致、表头被重复粘了 N 遍的那种）重排成一份总表，只保留一份表头，可选去掉完全重复的行。

之所以值得单独做，是因为"切文件"这件事最容易滑向两个不好的答案：一是随手写个 split('\n') 或 awk 按物理行硬切，遇到引号包裹的逗号、字段里带换行的记录就切出坏文件；二是把数据丢给在线转换站，几十兆的业务明细离开了本机。这里既不做前者那种不可靠的切法，也不做后者那种上传。

第二个动机是把口径讲明白。按体积拆分只能是"逼近"，因为不能把一条记录劈开；按列值拆分必然遇到空取值和重名取值；合并必然会碰到"这一份的首行到底是表头还是数据"。这些判定如果偷偷做，出问题时没人能发现。所以工具的每一条判定都在结果下方数据提示区写明：跳过了几个空行、几条记录独占超限分片、哪个列被丢弃、去掉了重复行、哪些取值合并进了同一片。

数据是怎么流动的？

拆分模式的链路（关键是全程保留原始文本，只在记录边界切）：

粘贴文本 / 上传单个文件 ↓ 识别分隔符（取前 10 行统计 , ; Tab | 的出现次数） ↓ 逐字符扫描：双引号内的逗号不分列、换行不分行，"" 还原为 " ↓ 每条记录同时记下【原始文本】与【解析后的列值】 ↓ 判定行尾风格（CRLF / LF 取多数；混用则提示） ↓ 按依据切分：行数计数 / 累加 UTF-8 字节 / 按取值分桶 ↓ 组装分片：表头行（按需）+ 原始记录文本 + 行尾 ↓ 预览选中分片 · 逐个下载 · 或打包 ZIP

合并模式的链路（这里是重建内容，不是拼接原文）：

文本框内容（作为第一份）+ 上传的多个文件 ↓ 各自解析，第一份的表头成为基准列顺序 ↓ 后续每份：首行与基准比对 → 一致丢弃 / 有共享列名则按列名对齐后丢弃 / 对不上则当数据保留 ↓ 按列名重排（缺列补空、多列丢弃）或按位置直接拼接 ↓ 可选：按整行文本去重 ↓ 输出 CSV：含逗号 / 引号 / 换行的单元格按 RFC4180 重新加引号

一句话口径：拆分是保真的（写出的还是原始字节，只在记录边界下刀），合并是重建的（按列对齐重新序列化，语义等价但写法可能被规范化）。

输入与输出

输入：左侧文本框粘贴 CSV / TSV 文本；或点上传文件读取 .csv / .tsv / .txt / .log（单个 ≤20MB，按 UTF-8 读取并自动跳过开头 BOM，GBK 文件请先转码）。拆分时取文本框内容或第一个文件；合并时文本框里的内容会作为第一份数据排在最前，之后按您选择的顺序接上各文件，一次最多 50 份。分隔符默认自动识别，也可手动指定逗号、分号、制表符、竖线。列数以基准行为准：勾选"首行为列名"时以表头那行为准，未勾选时以最宽的那一行为准，列名用"列1、列2……"占位。

输出：右侧文本框，拆分时是当前选中分片的内容（分片列表在下方，点一行即切换预览并可直接下载该分片），合并时是完整的合并结果。底部统计条：拆分给"分片数 / 数据行数 / 列数 / 当前分片名与体积"，合并给"数据源数 / 数据行数 / 列数 / 总体积"。再下方"数据提示"区列出本次所有口径说明与异常计数（同一类提示会自动合并去重，最多展示 15 条，超出会写明"另有 N 条提示已省略"）。文件下载一律带 UTF-8 BOM；扩展名跟随分隔符，制表符时得到 .tsv。

拆分示例（输入 5 行、每片 2 行、每片都写表头） id,name,city 1,A,SH 2,B,BJ 3,C,SH 4,D,GZ 5,E, → part-01.csv (2 行 · 27 B) / part-02.csv (2 行 · 27 B) / part-03.csv (1 行 · 18 B) part-02.csv 内容： id,name,city 3,C,SH 4,D,GZ 按"city"列取值拆分（升序，空值归片） → part-（空值）.csv (1 行) / part-BJ.csv (1 行) / part-GZ.csv (1 行) / part-SH.csv (2 行) 提示：1 条记录的取值列为空，已归入「（空值）」一片 取值列共 4 个不同取值，生成 4 片 合并示例（两份列顺序不同，按列名对齐） 第一份：订单号,地区,金额 → A001,华东,1200 / A002,华东,800 / A003,华南,2400 第二份：订单号,金额,地区 → B001,500,华北 / B002,900,华北 / A002,800,华东 → 订单号,地区,金额 A001,华东,1200 A002,华东,800 A003,华南,2400 B001,华北,500 B002,华北,900 A002,华东,800 提示：第 2 份的首行按列名对齐后丢弃（列顺序或列名与基准不同） 统计：数据源 2 · 数据行 6 · 列 3 · 体积 121 B

快速开始

  • 点载入示例：拆分模式下会灌入一份 15 行销售明细并自动按"地区"列切好，直接看到"华东 / 华北 / 华南 / 西南"四个分片长什么样；合并模式下载入的是两份列顺序不同的分表，能看见对齐与丢表头的效果。示例里的金额特意写成 "12,800.00" 这种带引号的千分位，方便您验证引号内逗号不会被切错。
  • 粘贴自己的数据或上传文件，把"操作"选成拆分或合并，选好"拆分依据"及参数，点执行。
  • 拆分结果在右下方分片列表里：点某一片可预览并单独下载，需要全部拿走就点打包 ZIP；改"文件名前缀"可控制分片命名。
  • 合并需要至少两份数据（文本框一份 + 至少一个文件，或两个文件），选"按列名对齐"或"按位置直接拼接"，按需勾"去除完全重复的数据行"，点执行后复制或下载一份结果。
  • 结果不符合预期时先看数据提示区——空行、未闭合引号、超大记录、被丢弃的列、对不齐的表头，全都会在那里写明原因。

三种拆分依据的差别

依据 参数 切出来是什么样 适用
按行数 每片行数（默认 1000） 片内记录数严格一致（最后一片可能更少），片体积随行长波动 接口分批导入、按条数核对、脚本按序逐片处理
按每片体积 每片不超过 N KB（默认 500） 逐条累加 UTF-8 字节数逼近上限；单条超限时它独占一片并提示 邮件附件超限、上传体积限制、Excel 打不开
按某一列的取值 取值列、每片取值数、取值顺序 取值相同的行同片，分片数等于取值组数（每片取值数 > 1 时会合并） 按地区 / 部门 / 渠道分发给不同负责人

命名规则统一为 前缀-标识.扩展名：按行数与按体积用两位起算的序号（part-01.csv），按列取值直接用清洗后的取值当标识（part-华东.csv），空取值用"（空值）"，重名追加 _2、_3。序号位数按分片总数自动扩展，200 片时用三位，保证按文件名排序就是按顺序排序。

关于"记录数"的算法：字段内含换行的记录算 1 条记录，不按物理行数计。所以"每片 1000 行"里的行指的是记录数，切出来的文件用文本编辑器打开可能看到超过 1000 个物理行——这是正确的，把多行算成一条才是真正的错。

合并的两条口径

一、后续文件的表头判定

该份首行与基准表头的关系 处理 提示区写法
列名完全一致 丢弃该行 第 i 份的首行与表头一致，已丢弃
有共享列名但顺序 / 增减不同 按列名对齐后丢弃该行 第 i 份的首行按列名对齐后丢弃
一个列名都对不上 作为数据保留 第 i 份的首行与表头对不上，已作为数据保留
取消勾选"丢弃后续文件的表头行" 一律不判断、不丢弃 重复表头会留在结果里

二、列对齐方式

方式 列顺序 它缺的列 它多出来的列 / 内容
按列名（默认） 以第一份为准重排 对应位置填空值，提示"缺少 N 列" 基准表头外的列丢弃并列名提示；数据行比表头宽时超出部分丢弃
按位置 原样直接拼接，不重排 短的补空，不报缺列 不删列，但列数不一致时提示"最多 N 列，与基准 M 列不一致，按位置拼接会错位"

两种方式的最终列数都以第一份数据为准。因此合并结果的形状由第一份决定：如果您希望保留最全的那套列，请把列最多的文件放在最前面（或粘进文本框）。

典型使用场景

  • 邮件 / 表单附件超限：按每片 5MB 拆分，接收方拿到分片后用本工具的合并模式原样拼回；只要不重复写表头，内容写法与原文一致。
  • 按负责人分发：按"地区"或"部门"列拆分，每个分公司收到一份带表头的 华东.csv，几百个取值也一次做完，不用手工筛选复制。
  • 接口分批导入：按 1000 行一片拆好，脚本按文件名顺序逐片提交，某片失败只需重传那一片，而不是整表重跑。
  • Excel 打不开的大文件：先按体积切成小片再逐片查看，定位脏数据时不必等整表加载。
  • 汇总各组回传的分表：列顺序有出入时选"按列名对齐"，一次合成总表；缺列补空、多列丢弃都会逐份写明，方便回退去补表头。
  • 压掉重复上报：合并时勾"去除完全重复的数据行"，同一批数据被传了两次的情况直接去掉并给出条数。
  • 清洗前置：勾掉"保留空行"看提示区的"跳过 N 个空行"，或用"未闭合引号"提示定位到具体行号，比整表倒进编辑器里翻找快得多。
  • 配合其他工具：拆分后各片可用 CSV 分组聚合 分别汇总再对账；需要看整体分布则接 数据统计；取值列本身不规范时先用 文本清理 统一。

工具优势

三种拆分依据：行数 / 体积 / 列取值 分片保留原始字节写法 只在记录边界下刀，绝不劈开一条记录 RFC4180 引号与字段内换行 表头按分片可选重复 分片逐个下载或打包 ZIP 合并按列名对齐，缺列补空 首行对不上时当数据保留，不吞数据 可选整行去重并报数 未闭合引号 / 空行 / 超限记录都给行号或条数 全程本地不上传

和"用 Excel 手工筛选复制"相比，它把几百个取值一次切完，并且每个分片的行数、体积都摆在统计条上；和在线拆分转换站相比，差别在数据根本没离开本机；和 split 命令或一句 awk 相比，差别在它们按物理行切，遇到带引号的千分位金额或字段内换行就会切出无法解析的坏文件，而这里按记录切。代价也很明确：它只处理"一份切多份、多份合一份"这一段，不做多表 join、不做压缩加密、不做跨文件传输，也不试图当超大 ETL 工具——那是服务器端流式任务的活，浏览器主线程做它们只会让您以为页面卡死了。

注意事项

  • 按体积是"逼近"不是精确。以整条记录为单位累加，每片体积通常落在上限之下、且略低于上限，收尾的那一片则明显偏小；只有单条记录本身超过上限时它才独占一片，那一片必然超限，提示区会写明有几条。要严格控制上传大小，请把上限设得比真实限制留足余量（例如限 5MB 时设 4MB）。
  • "每个分片都写入表头"会改变分片数。表头那一行的字节数会从每片额度里预扣，勾选状态不同，同一批数据的分片数可能不一样。关闭后只有第 1 片含表头，此时分片是"一份文件的碎片"而不是"各自可独立打开的表"。
  • 取值列的比较口径很朴素。只去首尾空格、区分大小写、不做全半角归一、不忽略不可见字符：SH 与 sh 是两个取值，华东 与 华东 （全角空格）也是两个。要按业务含义合并请先统一数据。
  • 取值太多时先看分片数。用日期、订单号、手机号这类高基数列当取值列会生成成百上千片；分片数超过 200 时多出的记录会并入最后一片（不丢数据但破坏"一个取值一个文件"的语义），提示区会写明。
  • 合并会重写引号。结果是按 RFC4180 重新序列化的：含分隔符、引号、换行的单元格会被加引号，原本"该加引号却没加"的写法会被修正。所以合并输出与原文件字节级不同属正常，语义一致。
  • 合并的列数由第一份决定。想保留全部列，请把列最全的文件放在最前（或粘进输入框）；否则后面文件多出来的列会被丢弃，虽然会提示，但内容已经不在结果里了。
  • 去重不等于业务去重。只有整行所有列都相同才算重复。按订单号、按主键去重请用 CSV 分组聚合 的去重计数或首个值。
  • 编码：文件一律按 UTF-8 读取，GBK 保存的中文 CSV 会整列乱码并导致取值列全是乱片，请先用 CSV 编码转换 转成 UTF-8。输出带 BOM 是为 Windows Excel 双击准备，若下游脚本只认无 BOM 的 UTF-8，请改用复制文本或自行去掉前三个字节。
  • 预览会截断，下载不会。单片内容超过约 200KB 时结果框只展示开头并提示已截断，分片下载与 ZIP 打包写入的是完整内容，二者长度可能不同，别以预览长度判断结果是否正确。
  • 容量与性能：单次 200000 行、单个文件 20MB、合并最多 50 份、分片最多 200 片；解析与切分在主线程同步完成，大文件点"执行"会有数秒停顿，必要时先按体积拆小再分批处理。输入变化会自动清空旧结果，避免拿着上一次的切点当本次结果。
  • 不做的事：不联网、不拆分非表格类文本、不保留 Excel 的样式与多工作表（.xlsx 请先另存为 CSV）、不做压缩加密以外的文件操作。需要看数据整体分布可用 数据统计，需要转成 JSON / SQL 可用 CSV 数据转换，需要找重复文件可用 重复文件查找。
