什么是表格转 SQL INSERT？

这是一款免费的在线工具，把 CSV / TSV / 从 Excel 复制的表格直接转换成可执行的 INSERT INTO 语句。手写插入语句又慢又容易漏引号、错转义，粘贴进来即可自动生成规范 SQL。

工具会自动做类型判断与转义：纯数字不加引号，字符串加引号并正确转义单引号与反斜杠，从源头避免语法错误与注入风险。全部处理在浏览器本地运行，数据表不上传。

支持的选项

  • 方言：MySQL（反斜杠转义 + 反引号标识符）或 PostgreSQL（双单引号转义 + 双引号标识符）。
  • 列名：可选是否在 INSERT 中显式列出列名，输出更清晰、列顺序更稳妥。
  • 空值转 NULL：空单元格生成 NULL（关闭则生成空字符串 ''）。
  • 批量分块：每 N 行合并为一条多值 INSERT，0 表示每行一条。
  • 标识符加引号：为表名/列名包裹反引号或双引号，兼容保留字与特殊字符。
  • 日期规范（默认开启）：将“年在前”的日期时间统一为 yyyy-mm-dd hh:mm:ss，并自动还原 Excel 日期序列号。

如何快速开始？

第一步：粘贴表格

把 CSV/TSV 或从 Excel 复制的内容粘贴进来（首行放列名），或点击"载入示例"体验。

第二步：填表名与方言

填写目标表名，选择 MySQL/PostgreSQL，设置分隔符与每批行数，勾选列名/空值/引号选项。

第三步：生成并执行

点击"生成 SQL"，右侧输出完整语句，下方统计行数→语句数；页面下方还会同步给出推断出的 CREATE TABLE 建表预览与已填数据的表格预览，可一并复制。

典型应用场景

初始化数据：把字典表 CSV 转成 INSERT，随建表脚本纳入版本管理。

快速导库：客户给的 Excel 名单临时入库，直接粘贴生成，省去写导入脚本。

数据修复：整理更正数据后转成补录语句，事务中执行并核对影响行数。

测试造数：把"模拟数据生成器"的表格转成 INSERT 铺底测试库。

特点与优势

本地处理，保护数据 MySQL / PostgreSQL 自动类型判断 注入安全转义 批量多值 INSERT 空值转 NULL 日期规范 yyyy-mm-dd hh:mm:ss 建表预览 CREATE TABLE 一键复制与下载

注意事项：

  • 仅生成文本 SQL，不连接数据库；执行前请核对列数、类型与目标表一致并做好备份。
  • 带前导零（如 007）、单位或空格的数字会按字符串处理，避免破坏编码。
  • 生成语句已做值转义以降低注入风险，但仍建议在可信环境执行。
  • 数据在浏览器本地处理，不会上传服务器，公共设备建议配合无痕模式。

常见问题

问：MySQL 和 PostgreSQL 有什么不同？

答：转义与标识符不同：MySQL 用 \' 反斜杠与反引号；PostgreSQL 用 '' 双单引号与双引号。

问："每批行数"怎么用？

答：填 0 每行一条 INSERT；填如 500 则每 500 行合成一条多值语句，语句更少、导入更快，适合大批量。

问：为什么数字有时加引号？

答：只有整体是数字才不加引号；带前导零、单位、空格的会当字符串加引号，防止破坏编码值。

问：从 Excel 复制过来列对不齐怎么办？

答：Excel 复制的单元格以制表符（Tab）分隔，将分隔符切换为 Tab 即可对齐；建议首行放列名，与数据列数一一对应。

问：长数字（如身份证、银行卡）会不会被转成科学计数法丢精度？

答：工具把超长、带前导零的数字视为字符串并加引号，不会写成科学计数法；若从 Excel 粘贴已被截断成 1.23E+17，请在 Excel 中先把该列设为文本再复制。

问：中文乱码、特殊字符能正确入库吗？

答：输出为 UTF-8 文本，中文、emoji 等直接写入字符串值；单引号、反斜杠按所选方言自动转义。下载 .sql 文件以 UTF-8 编码保存。

问：日期时间会被统一成什么格式？

答：开启“日期规范”后，“年在前”的日期时间（如 2024/1/5、2024-01-05 9:30）统一为 yyyy-mm-dd hh:mm:ss，纯日期保留为 yyyy-mm-dd；上传的 .xlsx 日期单元格（内部为序列号）也会自动还原。无需此行为时取消勾选即可。

问：能帮我生成建表语句吗？

答：能。生成 SQL 后，页面下方会展示“建表预览”：根据每列数据自动推断类型（整数→INT/BIGINT、小数→DECIMAL、日期→DATE/DATETIME、文本→VARCHAR 按实际长度），首列为唯一整数 id 时自动识别为主键，非空列加 NOT NULL；同时以表格形式预览前 20 行数据。类型仅供起步参考，正式建表前请复核。

问：会执行入库吗？

答：不会。只输出文本 SQL，请自行复制到数据库执行，并确保已备份。

生成示例：从表格到 SQL

输入表格（CSV，首行为列名）

id,name,age,city,salary,joined_at 1,张三,28,深圳市,8500.50,2024/1/5 2,O'Brien,35,"北京市, 朝阳",12000,2023-11-20 9:30 3,李四,,上海市,6000,

输出 INSERT（MySQL，勾选列名/空值转NULL/日期规范，每批行数=0）

INSERT INTO `users` (`id`, `name`, `age`, `city`, `salary`, `joined_at`) VALUES (1, '张三', 28, '深圳市', 8500.5, '2024-01-05 00:00:00'); INSERT INTO `users` (`id`, `name`, `age`, `city`, `salary`, `joined_at`) VALUES (2, 'O\'Brien', 35, '北京市, 朝阳', 12000, '2023-11-20 09:30:00'); INSERT INTO `users` (`id`, `name`, `age`, `city`, `salary`, `joined_at`) VALUES (3, '李四', NULL, '上海市', 6000, NULL);

要点解读

  • 28、8500.5 等纯数字不加引号；张三、北京市, 朝阳 作为字符串加引号。
  • O'Brien 的单引号被转义（MySQL 为 \'，PostgreSQL 为 ''），逗号不会被误拆列。
  • 2024/1/5 与 2023-11-20 9:30 统一为 yyyy-mm-dd hh:mm:ss；缺秒自动补 :00。
  • 空单元格（age、joined_at）生成 NULL。

同步生成的建表预览（CREATE TABLE）

CREATE TABLE `users` ( `id` INT NOT NULL AUTO_INCREMENT PRIMARY KEY, `name` VARCHAR(32) NOT NULL, `age` INT, `city` VARCHAR(48) NOT NULL, `salary` DECIMAL(10,2) NOT NULL, `joined_at` DATETIME ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

类型由每列实际数据推断：整数列→INT、金额→DECIMAL、日期→DATETIME、文本按长度→VARCHAR；首列唯一整数 id 自动设为主键，非空列加 NOT NULL。预览为起步参考，正式建表请根据业务复核。

  • 先输出列名：开启"输出列名"能明确字段对应关系，避免列顺序变化导致数据错位。
  • 大批量记得分块：上千行时把"每批行数"设为几百，合并成多值 INSERT，导入效率更高。
  • 事务包裹：执行时可自行用 BEGIN; ... COMMIT; 包住生成的语句，失败可整体回滚。
  • 配合 CSV / 模拟数据：先在"CSV 工具箱"清洗表格，或用"模拟数据生成器"造数，再转成 SQL。
  • 本地处理：数据表全程在浏览器，关闭页面即清除。
