工具介绍

Excel 一打开就乱码的 CSV，换个编码就好

  • 系统或数据库导出的 CSV 多为 GBK/GB18030 编码，Excel 默认按另一种编码解析，中文列全变成“æ±‰å­—”“娑堟伅”这类乱码；改成 UTF-8 又发现 Excel 2016 之前的版本不认无 BOM 的 UTF-8。本工具就是专门解决这一条链路：检测真实编码 → 重新解码 → 输出带 BOM 的 UTF-8，Excel 双击即正常显示。
  • 基于浏览器原生 TextDecoder 实现 GBK、GB18030、Big5、EUC-KR、Shift_JIS、UTF-16 等遗留编码的读取；输出 GBK/Big5 所用的字符映射表由浏览器解码器在本地即时反查构建，不引入任何第三方编码转换库。
  • 工具做的是字节级转码，不解析、不重排、不格式化 CSV：字段里的逗号、引号、换行、前后空格都逐字符原样保留，避免“转一次码多出几列”的二次伤害。

核心功能

  • 编码自动识别：BOM 优先、UTF-8 严格校验，再对 GBK/Big5/EUC-KR/Shift_JIS/Windows-1252 逐个解码打分；识别不准时可手动指定源编码立刻重解码。
  • 五种输出编码：UTF-8 + BOM（Excel 直开）、UTF-8 无 BOM（接口/Git 仓库友好）、GBK（ANSI 中文）、Big5（繁体资料交换）、UTF-16LE + BOM。
  • 质量报告：源字节数、检测编码、字符数、行列数、U+FFFD 替换符数量，以及输出时无法映射为 ? 的字符数量，乱码是否修好一眼可判。

使用说明

  1. 点击“上传 CSV/TXT”选择乱码文件（或点击“载入示例（GBK 文件）”先体验一次），文件内容会以自动识别出的编码解码显示在左侧。
  2. 如果左侧仍有乱码，把“源编码”手动改成 GBK/GB18030/Big5 等，页面会立即按新编码重新解码；确认文字正常后选择“输出编码”和“换行符”。
  3. 点击“转码”查看结果与输出统计，再点“下载”保存新文件（文件名自动追加编码后缀，如 -utf8bom），或点“复制”取用文本。

注意事项

  • “源编码”只在载入文件（有原始字节）时决定如何解码；直接粘贴的文本已经是浏览器解码后的 Unicode，此时只需选好“输出编码”。
  • 输出 GBK/Big5 时，映射表里没有的字符（emoji、生僻字、繁简混排中的另一侧字符）会写成 ? 并在统计中计数；若数量不为 0，建议改出 UTF-8 文件。
  • Big5 只收繁体字，用 Big5 输出简体内容会产生大量 ?；这类跨国资料交换建议统一 UTF-8 + BOM。
  • 工具不会替你判断“业务上正确的编码”：GBK 与 Big5 的字节流都可能被对方解成另一种“看起来通顺”的文字，请以预览语义为准。
  • 单文件建议不超过 50MB，超大会占用较多浏览器内存；全程本地处理，关闭页面即清除数据。

典型场景

  • 财务/运营对账：ERP 导出的 GBK 报表在 Excel 里是乱码，转成 UTF-8 + BOM 后双击即读，再进“CSV 数据转换”工具做去重与排序。
  • 银行与社保批量代付：网银前置机只认 ANSI(GBK) 文本，把 UTF-8 模板转回 GBK 上传，避免整批打回重做。
  • 两岸三地资料交换：台湾合作伙伴发来的 Big5 客户名单，在本地转成 UTF-8 后交给 CRM 导入，姓名不再是一串符号。
  • 开发调试：老项目遗留的 GBK CSV 测试数据，批量转 UTF-8 无 BOM，防止 Git 差异与前端解析出现 ï»¿ 头导致的字段名错乱。
  • 数据入库前的清洗接力：先把编码统一成 UTF-8，再用“表格转 SQL INSERT”生成导入语句，或用“Json/CSV 转图表”出汇报图。
