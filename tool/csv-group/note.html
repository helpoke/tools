这个工具在做什么？

它把 SQL 的 GROUP BY 和 Excel 的数据透视表 塞进了一个文本框：粘贴一份 CSV，点列名选分组维度，挑几个聚合算法，点一次"汇总"就得到结果；切到透视模式，再指定行字段、列字段、值字段与算法，就得到一张交叉表。

之所以值得单独立一个工具，是因为"把 CSV 分个组"这件小事通常会先要求您打开某个东西——Excel、Numbers、一段 pandas 环境、或者一个得先导入数据的数据库。而导出的报表里往往就躺着您要算的那份 CSV，几百行到几十万行都有。这里不需要安装、不需要注册、不需要联网。

第二个动机是口径可核对。金额列写成 1,234.50、¥99、12% 时，Excel 经常把整列识别成文本、求和结果静默变成 0；朴素的 split(',') 又会把引号里的逗号当成字段分隔符，汇总口径悄悄变了却看不出来。本工具按 RFC4180 解析引号与字段内换行，清洗后仍不能解析成数字的单元格一律计入"跳过"并在提示区报数，让差异摆在明面上。

数据是怎么流动的？

整条链路只有一次同步遍历，理解它有助于解释各种"为什么"：

粘贴文本 ↓ 识别分隔符（取前 10 行统计 , ; Tab | 的出现次数） ↓ 逐字符解析：双引号内的逗号 / 换行不分列不分行 ↓ 首行为列名？取作表头；否则列名用「列1、列2…」 ↓ 按选中的分组列取值拼键 → 哈希桶（保持首次出现顺序） ↓ 每喂进一行，同时更新该分组的每个聚合器 ↓ 排序（聚合值降序 / 分组键升序 / 原顺序）→ 截断前 N 行 ↓ 输出 CSV / JSON / Markdown

透视模式复用同一套桶结构：行字段的值做主键，列字段的值做子键，格子里放值字段的聚合器。行合计、列合计与右下角总计各自持有独立的聚合器，用同一算法在该行（列）的全部明细上复算，因此平均、去重、最大最小的合计不等于格子结果的再运算。

一句话口径：凡是"求和 / 平均 / 最大 / 最小"，只有能解析成数字的单元格参与；空串、-、N/A、null、无、空 以及纯文本都被视为缺失，计入跳过数，绝不当成 0。

输入与输出

输入：左侧文本框粘贴任意 CSV / TSV 文本，或上传 .csv / .tsv / .txt / .log 文件（≤20MB，按 UTF-8 读取并自动跳过开头 BOM；GBK 文件请先转码）。分隔符默认自动识别，也可手动指定逗号、分号、制表符、竖线。列数以基准行为准：勾选"首行为列名"时以表头那行为准，未勾选时以最宽的那一行为准；比基准短的行缺的列按空值处理，比基准长的行多出的列忽略，两种情况都会在提示区计数。

输出：右侧文本框是结果表，可选三种格式—— CSV（带 BOM，行分隔符 CRLF，含逗号 / 引号 / 换行的单元格自动加引号转义）、JSON（对象数组，数值列为 number，缺失为 null）、Markdown 表格（可直接贴进文档，单元格里的竖线会转义、换行压成空格）。底部统计条给出行数、列数、分组数 / 行列数、输出行列数；再下面的"数据提示"区列出本次的口径说明与异常计数。

快速开始

  • 点载入示例：一份 15 行销售明细会立刻按"地区"跑出求和与计数，先看结果形状，再照自己的数据结构对照。
  • 粘贴自己的数据；列名会自动出现在"分组列"里，点一个或多个列名选择分组维度，点击的先后就是层级的先后。
  • 在"聚合列"选算法与列后点添加，可叠加多个；一个都不加时默认输出每组的计数。
  • 需要交叉表就把"汇总方式"切成交叉透视表，指定行字段、列字段、算法、值字段，勾上"添加行列合计"。
  • 按需用结果排序、小数位、只看前 N 行、输出格式调整，然后复制或下载。

九种聚合算法的口径

算法 要求 空值 / 非数值的处理 结果类型
计数 不需要选值字段（选"（全部行）"） 逐行 +1，与值内容无关，空行也计入 整数，不受小数位选项影响
去重计数 必须选值字段 空串不参与；其余按去掉首尾空格后的文本比较，区分大小写 整数，不受小数位选项影响
求和 必须选值字段 非数值单元格跳过并计入提示；全部跳过时该组结果为空（不输出 0） 数值
平均值 必须选值字段 分母是有效数字的个数，不是行数 数值
最小值 / 最大值 必须选值字段 只在能解析成数字的值里比较 数值
首个值 / 末尾值 选值字段 取该列在组内第一个 / 最后一个非空的原样文本 文本
拼接文本 选值字段 忽略空值，最多保留前 50 个，超出以 … 结尾；用 / 分隔 文本

透视模式提供其中 6 种（求和、计数、去重计数、平均、最小、最大），因为交叉表的格子必须是可比较的单值。同一个值字段被求和与平均同时使用时，非数值的跳过判定完全一致，两者可以互相对账：求和 ÷ 有效数字个数 = 平均。

典型使用场景

  • 报表核对：按地区汇总金额、订单数、客单价，确认给领导的数字与自己逐行算的一致。
  • 日志速判：状态码 × 接口路径分组计数，一眼看出哪个链路在集中报错，不必把日志导进任何平台。
  • 周报交叉表：行渠道 × 列月份 × 值销售额，附行列合计，输出 Markdown 直接贴进周报或 IM 文档。
  • 基数评估：用去重计数看某列的用户数 / SKU 数 / 订单号数，决定入库前要不要建字典表或索引。
  • 双向对账：两份明细各跑一次同口径分组求和，比对差额落在哪个维度，比逐行 diff 快一个量级。
  • 接口联调：把分组结果输出成 JSON 数组，直接当图表数据或 mock 返回值。
  • 清洗前置：勾掉"首行为列名"看纯数据行的分组结果，用提示区的"分组键为空"计数定位缺失字段。

工具优势

多列分组，点选顺序即层级 九种聚合可叠加 行×列交叉透视带行列合计 RFC4180 引号与内嵌换行 千分位 / 货币 / 百分号容错 非数值跳过并报数 合计按同口径复算 CSV / JSON / Markdown 三输出 列名变化按名称保留选择 全程本地不上传

和"把数据粘进 Excel 拖透视表"相比，差别不在速度而在可复现：这里的每一步都写在提示区，跳过几个单元格、几行列数不齐、几个空分组键，全都能报给您，换个人重新做一遍结果一致；把数据丢给在线转换站则要承担资料外传的风险。与国内常见的"必须装客户端才能做透视"相比，它免安装；与 pandas 相比，它免环境。代价是它只做"分组—聚合—输出"这一段，不做多表 join、不做时间粒度重采样，需要那些请回到代码里。

注意事项

  • 分组键是纯文本比较。只去掉首尾空格，不区分大小写、不做全半角归一、不忽略不可见字符：华东 与 华东 （全角空格）会被分成两组。建议先用 文本清理 或 行处理 工具统一，再来做汇总。
  • 百分号只去符号、不除以 100。12% 按 12 参与求和与平均，这样一批带百分号的完成率求和得到的是"百分点之和"。要按小数口径统计，请先整列除以 100。
  • 透视列宽由列字段的基数决定。用日期、订单号、手机号这类高基数列当列字段会生成极宽的表；超过 200 个列值时只取排序后的前 200 个并在提示区写明总数，剩下的值不会出现在任何格子里，因此合计仍按全部明细复算，可能与可见格子之和不一致。
  • 行字段与列字段选了同一列时，只有对角线有值，提示区会直接要求您换成两个不同的列。
  • 排序的三种模式含义固定：按第一个聚合值降序（非数值视为最小沉底，同值再按分组键升序）、按分组键升序（数字优先于文本，多列时逐列比较）、保持出现顺序。只看前 N 行在排序之后截断，统计条里的分组数仍是全量数。
  • 小数位选项只影响数值显示：自动模式最多保留 6 位有效小数（按四舍五入截断），计数与去重计数恒为整数。求和的精度就是 IEEE 754 双精度的结果，大额金额建议用整数分单位再汇总。
  • 容量与性能：单次 200000 行、上传 20MB 以内；解析与汇总在主线程同步完成，大文件点击"汇总"会有数秒停顿，可分批处理。输入时的列名预览只读取开头 4000 个字符，所以边打字边看不会卡。
  • 编码：文件按 UTF-8 读取，GBK 保存的中文 CSV 会整列乱码并导致分组键异常，请先用 CSV 编码转换 转成 UTF-8。
  • 不做的事：不联网查询、不与其他文件 join、不生成图表、不写回原文件。需要把大 CSV 拆开后分批处理，可用 CSV 拆分合并；需要把扁平数据转成层级结构，可用 扁平数据转树形。
