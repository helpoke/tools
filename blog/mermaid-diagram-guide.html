用代码画图：如何使用 Mermaid 快速绘制架构图与时序图

📅 2026-08-09 ⏱️ 阅读时长：18分钟

前言：为什么要用代码画图

在软件开发过程中，架构图、流程图、时序图是沟通系统设计的重要工具。传统的绘图工具（如 Visio、Draw.io）虽然功能强大，但存在诸多问题：版本控制困难、协作效率低、修改成本高、图片与代码分离。Mermaid 作为一种基于文本的图表定义语言，完美解决了这些痛点。通过简单的文本描述，就能生成专业的技术图表，支持版本控制、团队协作和自动化渲染，正成为现代开发团队的首选绘图工具。

一、Mermaid 简介：什么是 Mermaid，优势何在

1.1 什么是 Mermaid

Mermaid 是一个基于 JavaScript 的图表绘制工具，它使用 Markdown 启发的文本定义来创建和动态修改图表。其核心理念是"文档即图表"——通过编写简单的文本代码，即可生成复杂的可视化图表。Mermaid 由 Knut Sveidqvist 在 2014 年创建，现已被 GitHub、GitLab、Notion 等主流平台原生支持。

1.2 Mermaid 的核心优势

特性 传统绘图工具 Mermaid
版本控制 困难（二进制文件） 简单（纯文本）
团队协作 需同步文件 支持 Git 协作
修改成本 高（重新排版） 低（修改代码）
文档集成 需插入图片 直接嵌入 Markdown
自动化 手动操作 支持脚本生成
跨平台 依赖软件 浏览器渲染

真实案例：某团队将架构图从 Visio 迁移到 Mermaid 后，图表修改时间从平均 30 分钟降低到 5 分钟，且每次修改都有清晰的 Git 记录，团队协作效率提升 60%。

1.3 支持的图表类型

  • 流程图（Flowchart）：用于表示算法、工作流程
  • 时序图（Sequence Diagram）：展示对象间的交互顺序
  • 甘特图（Gantt Chart）：项目计划和时间线
  • 类图（Class Diagram）：面向对象设计
  • 状态图（State Diagram）：系统状态转换
  • 实体关系图（ER Diagram）：数据库设计
  • 用户旅程图（User Journey）：用户体验流程
  • 饼图（Pie Chart）：数据占比展示

二、基础语法：流程图、时序图、甘特图、类图

2.1 流程图基础

流程图是最常用的图表类型，用于表示工作流程或算法逻辑。

基本语法：

graph TD
    A[开始] --> B{判断条件}
    B -->|是| C[执行操作1]
    B -->|否| D[执行操作2]
    C --> E[结束]
    D --> E

节点形状：

graph LR
    A[矩形节点]
    B(圆角矩形)
    C((圆形))
    D{菱形}
    E[[子程序]]
    F[(数据库)]
    G((圆形))
    H>不对称形状]
    I{{六边形}}

连接线类型：

graph LR
    A --> B     # 实线箭头
    A --- B     # 实线无箭头
    A -->|标签| B  # 带文字的连接
    A -.-> B    # 虚线箭头
    A ==> B     # 粗线箭头
    A --> B --> C  # 链式连接

2.2 时序图基础

时序图用于展示对象之间的交互顺序，特别适合表示 API 调用流程。

基本语法：

sequenceDiagram
    participant 用户 as User
    participant 前端 as Frontend
    participant 后端 as Backend
    participant 数据库 as Database
    
    User->>Frontend: 发起请求
    Frontend->>Backend: API调用
    Backend->>Database: 查询数据
    Database-->>Backend: 返回结果
    Backend-->>Frontend: 响应数据
    Frontend-->>User: 展示结果

消息类型：

sequenceDiagram
    A->B: 实线箭头
    A-->B: 虚线箭头
    A->>B: 实线空心箭头
    A-->>B: 虚线空心箭头
    A-xB: 实线叉号
    A--xB: 虚线叉号

生命线控制：

sequenceDiagram
    A->>B: 请求
    
    activate B
    B->>C: 处理
    activate C
    C-->>B: 响应
    deactivate C
    B-->>A: 返回
    deactivate B

2.3 甘特图基础

甘特图用于项目管理和时间线规划，可以直观展示任务进度和依赖关系。

基本语法：

gantt
    title 项目开发计划
    dateFormat YYYY-MM-DD
    
    section 设计阶段
    需求分析     :a1, 2026-01-01, 7d
    原型设计     :a2, after a1, 5d
    UI设计       :a3, after a2, 7d
    
    section 开发阶段
    前端开发     :b1, 2026-01-15, 14d
    后端开发     :b2, 2026-01-15, 14d
    联调测试     :b3, after b1 b2, 7d
    
    section 发布阶段
    部署上线     :c1, after b3, 3d
    监控优化     :c2, after c1, 7d

2.4 类图基础

类图用于面向对象设计，展示类的关系和结构。

基本语法：

classDiagram
    class Animal {
        +String name
        +int age
        +makeSound()
    }
    
    class Dog extends Animal {
        +String breed
        +bark()
    }
    
    class Cat extends Animal {
        +String color
        +meow()
    }
    
    Animal <|-- Dog
    Animal <|-- Cat

关系类型：

classDiagram
    A <|-- B  # 继承
    A *-- B   # 组合
    A o-- B   # 聚合
    A --> B   # 关联
    A --< B   # 实现
    A ..> B   # 依赖

三、高级用法：子图、样式、交互

3.1 子图（Subgraph）

子图用于将相关节点分组，增强图表的组织性。

流程图中的子图：

graph TB
    subgraph 前端系统
        A[用户界面] --> B[状态管理]
        B --> C[API调用]
    end
    
    subgraph 后端系统
        D[控制器] --> E[服务层]
        E --> F[数据访问]
    end
    
    C --> D
    F --> G[(数据库)]

时序图中的子图：

sequenceDiagram
    participant 用户
    participant 系统
    
    box Purple 系统模块
        participant 前端
        participant 后端
    end
    
    用户->>前端: 操作
    前端->>后端: 请求
    后端-->>前端: 响应
    前端-->>用户: 结果

3.2 样式定制

通过 style 和 classDef 命令可以自定义节点样式。

节点样式：

graph LR
    A[节点A] --> B[节点B]
    
    style A fill:#f9f,stroke:#333,stroke-width:2px
    style B fill:#bbf,stroke:#f66,stroke-width:2px,color:#fff

样式类：

graph LR
    A[节点A] --> B[节点B] --> C[节点C]
    
    classDef important fill:#f96,stroke:#333,stroke-width:4px;
    classDef minor fill:#9cf,stroke:#333,stroke-width:2px;
    
    class A important
    class B,C minor

3.3 交互功能

Mermaid 支持点击事件和工具提示，增强图表交互性。

点击事件：

graph LR
    A[文档] --> B[代码]
    B --> C[测试]
    
    click A "https://example.com/doc" "查看文档"
    click B "https://example.com/code" "查看代码"
    click C "https://example.com/test" "运行测试"

注意：点击事件需要在支持 JavaScript 的环境中才能正常工作。在某些 Markdown 渲染器中可能被禁用。

六、常见问题与解决方案

6.1 图表渲染失败

问题：图表无法渲染，显示错误信息。

原因：语法错误、特殊字符未转义、节点名称冲突。

解决方案：

  1. 使用在线编辑器验证语法
  2. 转义特殊字符：#quot; 代替引号，#lt; 和 #gt; 代替尖括号
  3. 检查节点 ID 是否唯一

6.2 中文显示问题

问题：中文节点名称显示异常。

解决方案：

# 使用引号包裹中文
graph LR
    A["开始节点"] --> B["结束节点"]

6.3 图表过于复杂

问题：大型图表难以阅读和维护。

最佳实践：

  • 分而治之：将大图拆分为多个小图，使用子图组织
  • 使用注释：添加 %% 注释 说明复杂逻辑
  • 抽象层次：合理设置抽象层次，避免过度细节
  • 命名规范：使用有意义的节点 ID 和标签

6.4 版本控制冲突

问题：多人修改同一图表导致冲突。

解决方案：

  1. 将图表拆分为多个模块，减少编辑冲突
  2. 使用有意义的节点 ID，避免随意重命名
  3. 在提交前与团队成员协调修改内容
