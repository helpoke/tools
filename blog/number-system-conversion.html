进制转换与计算机数制基础：二进制、八进制、十六进制

📅 2026-08-24 ⏱️ 阅读时长：14分钟

引言：为什么计算机"只认识"0 和 1

人类使用十进制（因为十根手指），但计算机使用二进制——因为物理世界中晶体管只有"导通"和"截止"两种状态。 理解进制转换不仅是为了应付面试题，更是理解计算机底层行为的基础：为什么 0.1 + 0.2 !== 0.3？为什么颜色用 #FF0000 表示？为什么内存地址用十六进制？这些问题的答案都藏在数制基础中。

一、进制的数学本质

1.1 位置计数法

任何进制都遵循同一个规则：每个数位的值 = 数字 × 基数的幂次

十进制 357 的含义：
  3 × 10² + 5 × 10¹ + 7 × 10⁰
  = 300 + 50 + 7 = 357

二进制 1011 的含义：
  1 × 2³ + 0 × 2² + 1 × 2¹ + 1 × 2⁰
  = 8 + 0 + 2 + 1 = 11（十进制）

十六进制 0xFF 的含义：
  F(15) × 16¹ + F(15) × 16⁰
  = 240 + 15 = 255（十进制）

通用公式：N = dₙ×bⁿ + dₙ₋₁×bⁿ⁻¹ + ... + d₁×b¹ + d₀×b⁰
  其中 b = 基数（2, 8, 10, 16...），d = 该位上的数字

二、四种常用进制

2.1 二进制（Binary）

基数：2    数字范围：0, 1
前缀：0b（编程中）

8 位二进制（1 字节）能表示：0 ~ 255
  00000000 = 0
  00000001 = 1
  11111111 = 255
  共 2⁸ = 256 个值

为什么计算机用二进制？
  物理层面：晶体管只有开/关两种状态
  数学层面：二进制运算规则最简单
  可靠性：两种状态容易区分，抗噪声能力强

2.2 八进制（Octal）

基数：8    数字范围：0-7
前缀：0o（JavaScript）或 0（C/Java 旧标准）

与二进制的关系：每 3 位二进制 = 1 位八进制
  二进制：110 101 010
  八进制：  6   5   2  → 0o652

为什么用八进制？
  3 位二进制一组，转换方便
  Unix 文件权限用八进制表示：chmod 755
  755 = rwxr-xr-x（所有者读写执行，其他人读执行）

2.3 十六进制（Hexadecimal）

基数：16   数字范围：0-9, A-F（A=10, B=11, ..., F=15）
前缀：0x（编程中）

与二进制的关系：每 4 位二进制 = 1 位十六进制
  二进制：1111 0000 1010 1100
  十六进制： F    0    A    C  → 0xF0AC

为什么编程中大量使用十六进制？
  1. 与二进制转换极其方便（4位一组）
  2. 颜色表示：#FF0000 = RGB(255,0,0)
  3. 内存地址：0x7FFF5FBFF6C0
  4. 字符编码：U+4E2D（"中"的 Unicode 码点）
  5. 位掩码：0xFF = 低 8 位全为 1

三、进制转换方法

3.1 十进制 → 其他进制（除基取余法）

将 255 转换为二进制：
  255 ÷ 2 = 127 ... 余 1  ← 最低位
  127 ÷ 2 = 63  ... 余 1
   63 ÷ 2 = 31  ... 余 1
   31 ÷ 2 = 15  ... 余 1
   15 ÷ 2 = 7   ... 余 1
    7 ÷ 2 = 3   ... 余 1
    3 ÷ 2 = 1   ... 余 1
    1 ÷ 2 = 0   ... 余 1  ← 最高位
  
  结果：11111111（从下往上读）

将 1000 转换为十六进制：
  1000 ÷ 16 = 62 ... 余 8   ← 最低位
   62  ÷ 16 = 3  ... 余 14(E)
    3  ÷ 16 = 0  ... 余 3   ← 最高位
  
  结果：0x3E8

3.2 其他进制 → 十进制（按权展开法）

二进制 1010 → 十进制：
  1×2³ + 0×2² + 1×2¹ + 0×2⁰ = 8 + 0 + 2 + 0 = 10

十六进制 0x1A3 → 十进制：
  1×16² + 10(A)×16¹ + 3×16⁰ = 256 + 160 + 3 = 419

3.3 二进制 ↔ 十六进制（最简便的方法）

二 → 十六：每 4 位一组，从右往左
  1110 0101 1010 → E    5    A → 0xE5A

十六 → 二：每位展开为 4 位
  0x3F → 0011 1111 → 111111

二 → 八：每 3 位一组
  110 101 010 → 6 5 2 → 0o652

八 → 二：每位展开为 3 位
  0o755 → 111 101 101 → 111101101

四、负数的二进制表示：补码

4.1 原码、反码、补码

计算机用补码表示有符号整数——这种表示法让加法和减法使用同一套电路：

以 8 位整数为例（范围 -128 ~ 127）：

+5 的表示：
  原码：00000101（最高位是符号位，0=正）
  反码：00000101（正数不变）
  补码：00000101（正数不变）

-5 的表示：
  原码：10000101（最高位是符号位，1=负）
  反码：11111010（符号位不变，其余取反）
  补码：11111011（反码 + 1）

为什么用补码？
  补码的好处：加法电路同时处理减法
  5 + (-3) = 00000101 + 11111101 = 00000010 = 2 ✓
  （忽略最高位的进位溢出）

特殊值：
  10000000 → 补码表示 -128（没有对应的原码）
  这就是为什么 8 位有符号整数范围是 -128 ~ 127（不是 -127 ~ 127）

五、位运算：直接操作二进制

5.1 六种位运算符

与（AND）&：两位都为 1 结果才为 1
  1010 & 1100 = 1000

或（OR）|：有一位为 1 结果就为 1
  1010 | 1100 = 1110

异或（XOR）^：两位不同结果为 1
  1010 ^ 1100 = 0110

取反（NOT）~：0 变 1，1 变 0
  ~1010 = ...11110101（补码取反）

左移（<<）：所有位向左移，右边补 0
  00001010 << 2 = 00101000（相当于 ×4）

右移（>>）：所有位向右移
  00101000 >> 2 = 00001010（相当于 ÷4）

5.2 位运算的实战应用

1. 判断奇偶
   n & 1 === 0  → 偶数
   n & 1 === 1  → 奇数

2. 快速乘除 2 的幂
   n << 3  → n × 8
   n >> 2  → n ÷ 4（向下取整）

3. 交换两个变量（不使用临时变量）
   a ^= b; b ^= a; a ^= b;

4. 权限标志位（Unix 风格）
   const READ    = 0b001;  // 1
   const WRITE   = 0b010;  // 2
   const EXECUTE = 0b100;  // 4
   
   let perm = READ | WRITE;     // 0b011 = 3（读写权限）
   perm & READ    // → 1（有读权限）
   perm & EXECUTE // → 0（无执行权限）
   perm |= EXECUTE;  // 添加执行权限 → 0b111 = 7
   perm &= ~WRITE;   // 移除写权限 → 0b101 = 5

5. 提取特定位（掩码操作）
   0xFF & value  → 取低 8 位
   (0xFF00 & value) >> 8  → 取第 8-15 位

六、浮点数的二进制存储：IEEE 754

为什么 0.1 + 0.2 !== 0.3？答案在 IEEE 754 浮点数标准中：

IEEE 754 双精度（64 位）结构：
  1 位符号位 + 11 位指数位 + 52 位尾数位

0.1 的二进制表示：
  0.1 × 2 = 0.2 → 取 0
  0.2 × 2 = 0.4 → 取 0
  0.4 × 2 = 0.8 → 取 0
  0.8 × 2 = 1.6 → 取 1
  0.6 × 2 = 1.2 → 取 1
  0.2 × 2 = 0.4 → 取 0  ← 开始循环！
  
  0.1 = 0.00011001100110011...（无限循环）
  → 52 位尾数存不下 → 截断 → 精度丢失

0.2 同样无法精确表示
  → 0.1 + 0.2 的实际结果：0.30000000000000004

解决方案：
  ✓ 比较浮点数时使用 epsilon：Math.abs(a - b) < 1e-10
  ✓ 金额计算使用整数（分）而非浮点数（元）
  ✓ 需要高精度时使用 BigInt 或 decimal.js 库

七、痛点深挖：进制转换工具和代码里的"隐形错误"

即使理解了原理，开发者在实际使用进制转换时仍会踩到几类高频陷阱——它们不会报错，但结果就是不对：

  • JS 大整数精度丢失：parseInt("0xFFFFFFFFFFFFFFFF", 16) 看似正常，但 JavaScript 的 Number 只有 53 位安全整数，超过 Number.MAX_SAFE_INTEGER（9007199254740991）后相邻整数无法区分。转 64 位哈希或颜色值时，必须改用 BigInt：BigInt("0x" + hex)。
  • 负数的进制转换：-255 转十六进制，不少人得到 -FF。这在数学上没错，但计算机内存里存的是补码：32 位下 -255 是 0xFFFFFF01。写底层工具时务必明确"数学表示"还是"内存表示"。
  • 前导零被吞：把 0x0F 转成二进制得到 1111，转回十六进制却是 F。在按位对齐的协议解析（如 IP 报文、寄存器配置）中，丢掉前导零会让字段错位。转换后应手动按 4 位一组补零。
  • parseInt 的老陷阱：老浏览器里 parseInt("08") 按八进制解析为 0。虽然 ES5 后默认十进制，但遇到 "0x" 前缀仍会自动切十六进制——处理用户输入时永远显式传第二个参数：parseInt(str, 10)。
  • 字符编码混淆："128 的二进制是多少"——如果没说明是 ASCII 码还是数值 128，答案完全不同（10000000 vs ASCII 里不存在）。工具类项目里，进制转换永远要标注"这是数值还是字符的码点"。

自查建议：写完转换代码后用一组"边界值"验证——0、最大值、最小值、负数、含前导零的数。任何一项对不上，都说明进位或符号处理有误。

八、深入原理：IEEE 754 浮点数的完整位布局与精度边界

前面提到 0.1 + 0.2 !== 0.3，但这只是冰山一角。IEEE 754 浮点数标准中还有几个关键概念——次正规数、精度边界、特殊值——它们在生产环境中都可能引发 bug。

8.1 单精度 vs 双精度：完整位布局

IEEE 754 双精度（64 位）完整结构：
  ┌─────┬────────────┬─────────────────────────────┐
  │ 符号 │ 指数(11位) │ 尾数(52位)                  │
  │ 1位  │ 0~2047     │ 隐含前导1 + 52位小数       │
  └─────┴────────────┴─────────────────────────────┘

  实际值 = (-1)^符号 × 1.尾数 × 2^(指数-1023)

  示例：-12.375 的存储
  符号：1（负数）
  绝对值：12.375 = 1100.011₂ = 1.100011 × 2³
  指数：3 + 1023 = 1026 = 10000000010₂
  尾数：1000110000...000（52位，前导1隐含）

  最终 64 位：
  1 10000000010 1000110000000000000000000000000000000000000000000000

单精度（32 位）对比：
  1 位符号 + 8 位指数 + 23 位尾数
  精度只有 ~7 位十进制有效数字
  示例：123456789.0f → 存储为 123456792.0（丢失精度！）

8.2 次正规数（Subnormal）：精度悬崖边的安全网

当指数为 0 时，IEEE 754 不再隐含前导 1，而是用前导 0——这就是次正规数（也叫非正规数）。它们填补了 0 和最小正规数之间的“空隙”，避免突然下溢到零：

正规数范围（指数 1~2046）：
  最小正规数 = 1.0...0 × 2^(1-1023) = 2^(-1022) ≈ 2.225×10⁻³⁰⁸

次正规数范围（指数 = 0）：
  最大次正规数 = 0.111...1 × 2^(-1022) ≈ 2.225×10⁻³⁰⁸
  最小次正规数 = 0.000...1 × 2^(-1022) = 2^(-1074) ≈ 4.94×10⁻³²⁴

  特点：次正规数的精度随数值减小而降低
  → 越接近 0，有效位数越少（“渐进下溢”）

特殊值：
  指数全 1 + 尾数全 0 = ±Infinity
  指数全 1 + 尾数非 0 = NaN
  指数全 0 + 尾数全 0 = ±0（存在 +0 和 -0！）

  +0 === -0 在 JS 中返回 true（规范要求）
  但 Object.is(+0, -0) 返回 false
  1/+0 = +Infinity，1/-0 = -Infinity（可区分）

8.3 精度边界：什么时候会“丢失”数字？

JavaScript 精度边界实战：

  // 安全整数边界
  Number.MAX_SAFE_INTEGER = 2⁵³ - 1 = 9007199254740991
  超过此值后，相邻整数无法区分：
  9007199254740992 === 9007199254740993  // true！

  // 浮点精度边界
  0.1 + 0.2 = 0.30000000000000004  // 不是 0.3
  0.1 + 0.7 = 0.7999999999999999   // 不是 0.8
  1.0 - 0.9 = 0.09999999999999998  // 不是 0.1

  // 大数吃小数
  1000000000000000.0 + 1.0 = 1000000000000000.0  // 1 被“吃掉”了
  因为 52 位尾数只能表示 ~15.9 位十进制有效数字

  // 解决方案
  ✓ 金额计算：转为整数分（100 分 = 1 元）
  ✓ 高精度：使用 BigInt 或 decimal.js
  ✓ 比较浮点数：Math.abs(a - b) < Number.EPSILON
  ✓ 显示时：toFixed() 但注意它也有舍入问题

九、技术选型决策：Integer vs Float vs Decimal vs BigInt

选错数值类型是“计算结果不对”的高发原因。以下是完整的选型指南：

数值类型对比：
┌─────────────┬──────────┬──────────┬──────────┬──────────────┐
│   类型       │ 精度     │ 范围     │ 运算速度 │   适用场景   │
├─────────────┼──────────┼──────────┼──────────┼──────────────┤
│ 整数 (int)  │ 精确     │ 受位宽限制│ ✓ 最快   │ 计数、索引、 │
│             │ 无误差   │          │          │ 权限标志     │
├─────────────┼──────────┼──────────┼──────────┼──────────────┤
│ 浮点 (float)│ ~15位    │ ±10³⁰⁸  │ ✓ 快     │ 科学计算、   │
│ (double)    │ (双精度) │          │ (硬件FPU)│ 图形/物理    │
├─────────────┼──────────┼──────────┼──────────┼──────────────┤
│ Decimal     │ 可配置   │ 可配置   │ △ 慢     │ 金额、财务、 │
│ (高精度)    │ 精确     │          │ (软件模拟)│ 精确小数     │
├─────────────┼──────────┼──────────┼──────────┼──────────────┤
│ BigInt      │ 精确     │ 无限     │ △ 中等   │ 密码学、     │
│             │ 无误差   │          │          │ 大整数运算   │
└─────────────┴──────────┴──────────┴──────────┴──────────────┘

决策树：
  你的数据是什么类型？
  ├── 计数/索引/ID → 整数（int / long）
  ├── 金额/货币 → Decimal（精确小数，不丢分）
  │   └── 或转为最小单位整数（分/厘）
  ├── 科学计算/图形学 → 浮点（double）
  │   └── 注意精度边界，用 epsilon 比较
  ├── 超大整数/密码学 → BigInt
  └── 用户输入的“任意数字” →
      ├── 包含小数点 → Decimal
      └── 纯整数 → BigInt

各语言推荐：
  JavaScript：整数用 Number，金额用 BigInt 或 decimal.js
  Python：整数自动大数，金额用 decimal.Decimal
  Java：金额用 BigDecimal，大整数用 BigInteger
  Go：金额用 int64（分）或 shopspring/decimal 库

关键原则：
  ✓ 永远不要用浮点数表示金额（0.1 + 0.2 ≠ 0.3）
  ✓ 浮点数比较用 epsilon，不要用 ===
  ✓ 大整数用 BigInt/BigInteger，不要用 Number
  ✗ 不要用 float 做迭代累加（误差会累积）

结语

进制转换是理解计算机底层行为的钥匙。二进制是硬件的语言，八进制是权限的密码，十六进制是程序员的眼镜，而 IEEE 754 浮点数则是"精度陷阱"的根源。掌握这些数制基础和位运算技巧，你就能更深刻地理解编程语言的行为，写出更高效、更可靠的代码。
