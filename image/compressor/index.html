    没有最优的压缩算法，只有最适合自己的压缩策略。不同的压缩算法适用于不同的场景：
    - 默认压缩：平衡质量和大小，保持原始图片格式。不适用于PNG透明图片。推荐场景：一般JPG图片，需要保持原始格式的非透明图片
    - 无损压缩：保持最高质量和原始扩展名。不推荐用于JPG图片，会导致图片增大或无法有效压缩。推荐场景：PNG透明图片、需要保留完整图像信息
    - 强力压缩：优先减小文件大小，统一转换为JPG格式以获得最佳压缩率，会显著降低图像质量。推荐场景：极致减小文件体积，对图像质量要求不高
    - WebP格式：现代浏览器高效图像格式，能在保持较高质量的同时显著减小文件体积。推荐场景：网站图片、支持WebP的应用，追求高质量和小体积平衡。推荐场景：一般JPG图片，需要保持原始格式的非透明图片

    图片压缩：在画质与体积之间找到最优平衡

    一、为什么你需要专业的图片压缩工具

    • 手机拍的照片动辄 5-10MB，上传到网站慢如蜗牛；电商详情页几十张产品图加起来上百 MB，页面加载超过 3 秒就会流失 40% 的用户。图片压缩不是简单地"降低画质"——而是在人眼几乎无法察觉差异的前提下，将文件体积缩小 60%-90%。
    • 本工具使用 Canvas API 重新编码图片——通过调整质量参数（0.1-1.0）精确控制压缩程度。实时显示原始大小、压缩后大小、压缩率和尺寸信息。批量压缩支持——一次上传多张图片，统一设置参数后一键全部压缩并打包下载。
    • 所有处理在浏览器本地完成，图片不上传到任何服务器。电商卖家、自媒体运营、前端开发者都能大幅提升工作效率——批量处理 20 张产品图通常只需 10-20 秒。

    二、压缩算法在做什么

    • JPEG 压缩原理：JPEG 使用离散余弦变换（DCT）将图片从空间域转换到频率域，然后对高频分量（人眼不敏感的细节）进行大幅度量化——这就是"有损压缩"的本质。质量参数控制量化的激进程度。
    • PNG 压缩原理：PNG 使用 DEFLATE 算法（LZ77 + 霍夫曼编码），属于无损压缩。压缩空间主要来自颜色简化：将 24 位真彩色降为更少色深。压缩率通常不如 JPEG（一般 20%-50%），但不丢失任何像素信息。
    • WebP：Google 开发的现代图像格式，基于 VP8 视频编码，同等画质下比 JPG 小 25-35%，同时支持透明和动画。

    三、压缩控制参数详解

    • 质量滑块（0.1-1.0）：0.1 最大压缩，1.0 几乎无损。实际使用中 0.7-0.85 是最佳平衡点——体积大幅减小，画质肉眼几乎无法区分。
    • 实时预览对比：调整质量滑块时实时更新压缩后体积——无需下载就能看到效果。基于 Canvas toBlob API 实时编码。
    • 批量处理与打包下载：同时上传多张图片，统一参数后一键处理。处理完成后逐张下载或打包为 ZIP。
    • 尺寸缩放可选：除了质量压缩，还可以缩小图片尺寸。宽度限制为 1920px 可以额外减少 50%-70% 体积——像素总量大幅减少了。

    压缩操作全流程

    第一步：上传图片

    • 单张或批量上传：支持 JPG/PNG/WebP/GIF/BMP。每张图片显示原始大小和尺寸。
    • 批量上传：支持多选上传，最多20张图片。
    • 输出格式：JPG（体积最小）或 PNG（保留透明通道）。原图有透明区域选 JPG 时透明变白色。

    二、选择压缩算法

    • 默认压缩：平衡质量和大小，保持原始图片格式。不适用于PNG透明图片。
    • 无损压缩：保持最高质量和原始扩展名。推荐用于PNG透明图片。
    • 强力压缩：优先减小文件大小，统一转换为JPG格式。
    • WebP格式：现代浏览器高效图像格式，保持较高质量和小体积。

    三、调整压缩质量

    • 质量滑块：拖动滑块调整压缩质量（1%-100%）。
    • 质量越高：图像质量越好，但文件大小越大。
    • 质量越低：压缩率越高，但可能损失图像细节。
    • 推荐范围：70-90之间，可根据实际需求调整。

    四、设置最大尺寸

    • 最大宽度：设置图片压缩后的最大宽度（100-16384px）。
    • 最大高度：设置图片压缩后的最大高度（100-16384px）。
    • 最大大小：设置压缩后文件的最大大小（20KB到原文件大小）。

    五、执行压缩

    • 单张压缩：点击"压缩当前图片"按钮。
    • 批量压缩：点击"批量压缩所有图片"按钮。
    • 图片列表管理：多张图片以列表展示，每张可单独删除。
    • 文件命名：自动添加 _compressed 后缀，避免与原文件混淆。

    六、压缩算法选择建议

    • 一般场景：使用默认压缩，平衡质量和大小。
    • PNG透明图片：使用无损压缩，保留透明通道。
    • 追求最小体积：使用强力压缩或WebP格式。
    • 网站图片：使用WebP格式，现代浏览器支持。

    注意事项与常见问题

    数据安全与隐私

    • 四种压缩算法（libpng 有损、WebP、Canvas 质量调节、MozJPEG 优化）全部在浏览器 Web Worker 线程中运行。图片解码、重编码、质量调节等计算密集型操作均在本地 CPU 完成，全程零网络通信，即使处理机密商业素材也不会泄露。
    • 压缩过程中，原始图片和压缩结果仅存在于浏览器的内存（Blob URL）中。关闭标签页后，所有图片数据和 Worker 线程立即释放。工具不使用 IndexedDB 或 localStorage 缓存任何图片文件。
    • 批量处理企业内部设计素材、未发布产品图等敏感图片时，建议使用无痕模式。无痕模式下浏览器不会将访问过的图片 URL 写入历史记录，关闭后连 DNS 缓存也一并清除，最大程度保护商业隐私。

    二、压缩参数指南

    • 质量 80% 是最佳平衡点——SSIM（结构相似性指数）通常在 0.95 以上，肉眼几乎无法分辨差异。
    • 质量参数超过 90% 后，文件体积急剧增大（每增加 1% 质量可能增加 10-20% 体积）但人眼几乎无法分辨画质差异，性价比极低。对于网页展示用途，质量 80-85% 是最佳平衡点——画质损失微小但体积可减少 40-60%。
    • 质量参数低于 30% 时，JPG 格式会出现明显的块状伪影（色块和边缘毛刺），PNG 文件由于无损特性反而可能比高质量时更大（因为噪点增多导致压缩效率下降）。建议质量下限不低于 50%。
    • "最大文件大小"功能会自动迭代调整质量参数，直到满足目标体积要求。

    三、批量处理须知

    • 单次批量上限 20 张图片，超大批量建议分批处理以避免浏览器内存不足。
    • 批量处理时，当前所有参数设置会统一应用到每一张图片。
    • 处理期间请勿关闭标签页或刷新页面，否则进行中的任务会中断。
    • 大尺寸图片（>5MB）压缩可能需要 10-30 秒，请耐心等待进度条完成。

    常见问题解答

    • 压缩后文件反而变大：可能选择了不匹配的算法。JPG 图片请用默认压缩，PNG 透明图片请用无损压缩。
    • PNG 压缩后透明背景变黑：默认压缩和强力压缩不支持透明通道，请切换为无损压缩或 WebP 格式。
    • 如何为网站优化图片：推荐 WebP 格式 + 质量 80% + 最大宽度 1920px，可兼顾画质和加载速度。
    • 批量下载 ZIP 失败：检查浏览器是否允许该网站下载多个文件，或尝试减少批量数量。
