    GIF 合成：用图片序列创造动态影像

    一、GIF 动图的制作远比你想象的复杂

    • GIF 格式诞生于 1987 年，距今已近 40 年——但它仍然是互联网上最流行的动画格式。表情包、产品演示、教程步骤、数据可视化动图——GIF 无处不在。然而制作 GIF 并不简单：需要按顺序排列多张图片、设置每帧的显示时长、处理帧间过渡、优化文件大小——传统方法需要 Photoshop 的时间轴功能或专业动画软件。
    • 本工具让 GIF 制作变得极其简单：上传图片序列（支持 JPG/PNG/WebP），设置每帧时长（0.1-10 秒），预览动画效果，一键生成 GIF 文件。支持调整输出尺寸（缩放）和质量（颜色数量），在文件大小和画质之间找到平衡。
    • 基于 gif.js 库在浏览器端完成 GIF 编码——使用 Web Worker 并行处理帧数据，不阻塞主线程。生成的 GIF 可以直接预览和下载。整个过程不上传到任何服务器。

    二、GIF 格式的技术限制与应对

    • 无损但有限：GIF 使用 LZW 无损压缩——同一帧内的连续相同颜色像素会被高效压缩。这就是为什么纯色动画（如文字动画）的文件远小于复杂照片动画——前者有大量连续相同像素，后者几乎每个像素都不同。

    三、GIF 合成的核心参数

    • 帧时长控制：每帧的显示时间（单位：秒），范围 0.1-10 秒。0.1 秒/帧 = 10 FPS（流畅动画），0.2 秒/帧 = 5 FPS（幻灯片效果），0.5 秒/帧 = 2 FPS（慢速展示）。总时长 = 帧数 x 每帧时长。
    • 实时预览：上传帧图片后，按设定的帧时长循环播放预览。调整帧时长时预览立即更新——不需要重新生成 GIF 就能看到效果。
    • 输出尺寸缩放：原始帧图片可能被缩小后写入 GIF——缩放可以大幅减少文件大小（宽度减半，像素总量减少 75%）。建议动图宽度不超过 480px（社交媒体友好尺寸）。
    • Web Worker 并行编码：GIF 编码是 CPU 密集型任务——gif.js 使用 Web Worker 将编码工作分配到后台线程，主线程保持流畅响应。10 帧 480px 的 GIF 通常在 3-5 秒内完成编码。

    GIF 合成操作步骤

    上传帧图片

    • 点击上传：点击上传区域或拖拽图片到上传区域。
    • 批量上传：支持多选上传，最多5张图片。
    • 支持格式：支持 JPG、PNG、WebP、GIF、BMP 格式。

    二、调整顺序

    • 查看列表：已上传图片会显示在图片列表中。
    • 拖拽排序：拖拽图片调整GIF播放顺序。
    • 清空全部：点击“清空全部”按钮删除所有图片。

    三、GIF设置

    • 帧延迟：设置每帧之间的延迟时间（100-5000毫秒），值越小动画越快。
    • 循环次数：选择播放次数，包括无限循环、播放1/2/3/5次。
    • 输出宽度：设置GIF的输出宽度（100-800像素）。
    • 保持宽高比：勾选后自动保持图片宽高比。

    四、生成GIF

    • 点击生成：点击“生成GIF”按钮开始生成动图。
    • 进度显示：生成过程中显示进度条。
    • 预览效果：生成完成后自动预览GIF效果。
    • 下载GIF：点击“下载GIF动图”按钮保存结果。

    五、参数建议

    • 流畅动画：帧延迟设置为100-300毫秒。
    • 慢速动画：帧延迟设置为500-1000毫秒。
    • 表情动图：输出宽度设置为200-300像素。
    • 分享动图：输出宽度设置为400-512像素。

    注意事项

    数据安全

    • GIF 编码引擎基于 gif.js 库在浏览器 Web Worker 线程中运行。多帧图片的解码、缩放、调色板生成、帧合成等全部计算过程在本地 CPU 完成，全程零网络通信。即使合成包含商业敏感信息的截图动画，图片数据也不会被泄露。
    • 上传的源图片和编码中的 GIF 帧数据仅暂存在浏览器的 Worker 内存中。关闭标签页后，Worker 线程立即终止，所有图片数据和中间帧缓存即刻从内存中销毁。工具不使用任何持久化存储机制（localStorage、IndexedDB 等）保存图片。
    • 制作包含公司内部系统截图、未发布产品界面、客户数据等敏感内容的 GIF 教程或演示时，建议使用浏览器无痕模式。无痕模式确保浏览历史、DNS 缓存、临时文件等在关闭后彻底清除，避免敏感截图残留。

    二、GIF 格式限制

    • GIF 格式诞生于 1987 年，每帧最多支持 256 色（8 位调色板），这是格式本身的固有限制。将照片（数百万色）合成到 GIF 后，颜色会被量化到 256 色调色板，导致色彩简化和色带现象。如果需要高色彩保真度的动画，建议考虑 WebP 动画或 APNG 格式。
    • 最多支持 5 张图片合成一帧 GIF，超量建议分批处理。
    • 输出宽度最大 800px，超大尺寸建议先用裁剪工具调整。
    • GIF 文件大小与帧数、尺寸、颜色复杂度成正比，建议控制参数以减小体积。

    三、帧延迟参数建议

    • 表情包/流畅动画：100-200ms，每秒 5-10 帧。
    • 产品展示/步骤演示：300-500ms，每秒 2-3 帧，观看舒适。
    • 幻灯片/慢速切换：1000-2000ms，适合教程和图文展示。

    四、性能提示

    • 大尺寸图片生成GIF需要较长时间，请耐心等待。
    • 生成过程中不要关闭浏览器或刷新页面。
    • 建议在生成前先压缩图片以提高处理速度。
    • GIF文件大小与帧数、尺寸、颜色数量相关。

    常见问题

    • 生成后颜色失真：GIF 格式仅支持 256 色/帧，这是格式限制，非工具问题。
    • 动画太快/太慢：调整帧延迟值。值越小动画越快，值越大越慢。
    • GIF 文件太大：减少图片数量、降低输出宽度、或增大帧延迟。
    • 生成失败：检查图片格式是否受支持，单张图片不要超过 10MB。
