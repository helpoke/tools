本地文件加密：简单且安全

为什么需要文件加密

  • 在传输或备份敏感文件时，您可能需要先对文件进行加密，以防止未经授权的访问。本工具使用 AES-256-GCM 算法，提供认证加密。
  • 所有加密/解密操作在浏览器本地完成，文件内容不会上传到服务器，适合处理隐私文档、照片、视频等。

核心功能

  • AES-256-GCM：现代认证加密算法，同时保证机密性和完整性。
  • PBKDF2 密钥派生：密码经 100,000 次迭代和盐值派生为 256 位密钥。
  • 自包含格式：加密文件自动包含盐和 IV，解密时无需额外输入。
  • 本地处理：文件完全在浏览器内存中处理，处理完成后立即释放。

使用指南

加密步骤

  • 设置密码：使用强密码，解密时需要完全相同的密码。
  • 选择文件：点击上传或拖拽需要加密的文件。
  • 点击加密：下载 .enc 扩展名的加密文件。

解密步骤

  • 选择加密文件：上传 .enc 文件。
  • 输入密码：必须与加密时完全一致。
  • 点击解密：下载原始文件。

安全建议

  • 密码强度：建议使用 12 位以上包含大小写字母、数字和符号的密码。
  • 密码保管：工具不保存密码，忘记密码将无法解密文件。
  • 文件大小：大文件会占用较多浏览器内存，处理完成后请关闭标签页。

技术优势与典型场景

典型应用场景

  • 隐私文件保护：加密个人身份证件、财务资料、医疗记录等敏感文件，防止设备丢失或被盗后数据泄露。
  • 云端备份加密：在上传文件到网盘或云存储前，先对文件进行加密，即使云端账号被盗，攻击者也无法读取加密内容。
  • 文件安全传输：通过邮件、即时通讯或 U 盘发送机密文件时，先加密再传输，接收方通过单独渠道获取密码。
  • 企业数据归档：对重要合同、设计稿、源代码等商业资料进行本地加密归档，满足数据安全和合规要求。

技术优势

  • 认证加密：AES-256-GCM 同时保证机密性、完整性和认证功能，可检测文件是否被篡改。
  • 强密钥派生：PBKDF2 配合随机盐和 100,000 次迭代，有效抵御暴力破解。
  • 自包含格式：加密文件自动包含 magic、version、salt、iv 和密文，解密时无需额外参数。
  • 本地处理：文件完全在浏览器内存中加密/解密，不上传服务器，保护隐私。

安全使用建议

AES-256-GCM 是目前推荐的文件加密方案。请使用强密码并通过不同渠道发送密码。建议保留本地备份以防密码丢失。

常见问题

  • Q: 忘记密码能恢复吗？A: 不能。AES-256-GCM 的密钥由密码通过 PBKDF2 派生，没有密码就无法解密。请务必牢记密码或安全记录。
  • Q: 加密后文件会变大吗？A: 会略微增大——加密文件包含盐值（16 字节）、IV（12 字节）和认证标签（16 字节），总计增加约 44 字节。对于大文件可忽略不计。
  • Q: 同一个文件用相同密码加密两次，结果一样吗？A: 不一样。每次加密都会生成新的随机盐和 IV，所以密文不同。这是安全优势——攻击者无法通过对比密文判断两个文件是否相同。
  • Q: 加密大文件会很慢吗？A: AES-256-GCM 使用 Web Crypto API 原生实现，速度接近系统级加密库。100MB 文件通常在 1-3 秒内完成加密。
