什么是Token在线工具？

Token在线工具是一款专业的Token处理工具集，专为需要解析、生成和管理Token的用户设计。Token（令牌）是现代网络应用中广泛使用的身份认证和数据传输载体，特别是在RESTful API设计、微服务架构、单页应用（SPA）等场景中扮演着核心角色。相比传统的Session认证，Token具有无状态、可扩展、支持跨域等优势，是现代Web应用首选的身份认证方案。

工具提供三种核心功能：JWT解析验证、随机Token生成和JWT生成签名。JWT（JSON Web Token）是目前最流行的Token格式，由三部分组成：Header（头部，存储Token类型和签名算法）、Payload（载荷，存储用户信息和声明）和Signature（签名，确保Token未被篡改）。工具可以完整解析JWT各部分内容，使用密钥验证HMAC签名，检查Token是否过期。同时，工具可以生成各种类型的随机Token字符串，用于API密钥、会话标识、临时验证码等场景。此外，工具还支持JWT生成签名功能，可选择HS256/HS384/HS512算法，填写标准声明和自定义Claims，一键生成完整签名的JWT Token。

所有处理均在浏览器本地完成，Token内容不会上传到任何服务器。这意味着您的敏感Token信息始终处于您的完全控制之下，不会经过任何第三方服务器。

如何使用？

JWT解析功能

在输入框中粘贴JWT Token字符串（格式如：xxxxx.yyyyy.zzzzz），点击"解析"按钮。工具会自动将Token分割为三部分：Header（Base64URL解码后显示JSON格式）、Payload（Base64URL解码后显示包含用户信息和声明的JSON）、Signature（原始签名字符串）。同时，工具会验证Token的格式是否正确，检测是否包含过期时间（exp）声明，并提示Token是否已过期。解析结果以结构化的JSON格式展示，方便查看和分析Token内容。

Token生成功能

选择Token长度（16位、32位、64位、128位可选）和字符类型（纯数字、字母、字母数字混合、全部字符）。点击"生成"按钮，工具会基于加密安全的随机数生成器生成符合要求的随机Token字符串。生成的Token可用于API密钥生成、会话标识创建、临时验证码制作等场景。您可以多次生成直到获得满意的Token。

JWT生成功能

输入签名密钥（Secret），选择签名算法（HS256、HS384或HS512），填写Payload中的标准声明（iss签发者、sub主题、aud受众、jti唯一ID）和时间声明（iat签发时间、nbf生效时间、exp过期时间），还可输入自定义Claims（JSON格式）。点击"生成 JWT"按钮，工具自动构建Header和Payload，使用HMAC算法计算签名，生成完整的JWT Token。生成的JWT可直接粘贴到JWT解析功能中进行验证。

常见问题与解答

问：JWT的三个部分分别是什么？

答：JWT（JSON Web Token）由三部分组成，用点号（.）分隔：1) Header（头部）：JSON格式的Base64URL编码，指定Token类型（通常为JWT）和签名算法（如HS256、RS256）；2) Payload（载荷）：JSON格式的Base64URL编码，包含声明（Claims）信息，如用户ID（sub）、发行者（iss）、过期时间（exp）等；3) Signature（签名）：对Header和Payload的签名，用于验证Token是否被篡改。签名的计算方式通常是：HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)。

问：JWT和Session有什么区别？

答：JWT和Session的主要区别：1) 存储位置：Session数据存储在服务器端，JWT数据本身包含所有信息，存储在客户端；2) 状态管理：Session是有状态的（服务器需维护会话），JWT是无状态的（服务器无需存储）；3) 扩展性：JWT适合分布式系统和跨域场景，Session需要额外处理跨域共享；4) 安全性：Session依赖会话ID，JWT依赖签名算法和密钥；5) 性能：JWT无需查询数据库验证，但每次请求都需要传输完整Token；6) 失效处理：Session可随时失效，JWT在过期前无法主动失效（除非加入黑名单机制）。

问：如何确保JWT的安全性？

答：确保JWT安全性的措施：1) 使用强密钥：使用足够长度的随机密钥（HS256至少32字节，RS256使用2048位以上密钥）；2) 设置短期过期：Access Token过期时间设置较短（如15分钟-1小时），使用Refresh Token定期刷新；3) 验证所有声明：检查iss（发行者）、aud（受众）、exp（过期时间）等标准声明；4) 使用HTTPS：始终通过HTTPS传输Token，防止中间人攻击；5) 不存储敏感信息：Payload中的数据只是编码（非加密），不要存储密码等敏感信息；6) 防止重放攻击：在Token中加入nonce或jti声明，使用一次一密。

问：Token过期了怎么办？

答：Token过期的处理方式取决于Token类型和系统设计：1) 使用Refresh Token：颁发两个Token——短期Access Token（如15分钟）和长期Refresh Token（如7天），Access Token过期后用Refresh Token换取新的；2) 重新登录：对于不需要Refresh Token的系统，用户需要重新登录获取新Token；3) 自动刷新：前端在检测到Token即将过期时（如提前5分钟），自动调用刷新接口获取新Token；4) 优雅处理：前端应捕获401响应，自动触发刷新流程，避免用户感知。本工具的JWT解析功能会显示Token的过期时间（exp），帮助您判断Token状态。

问：为什么JWT的签名无法伪造？

答：JWT签名使用HMAC（对称加密）或RSA/ECDSA（非对称加密）算法：1) HMAC签名：使用服务器端独有的secret密钥对Header和Payload进行签名，只要密钥不泄露，攻击者无法生成有效签名；2) RSA签名：使用私钥签名，任何人可用公钥验证，但只有私钥持有者能签名。签名过程是：对Header和Payload的Base64URL字符串拼接后计算哈希，攻击者没有密钥无法计算出正确的签名值。本工具仅验证签名格式正确性（是否为有效的Base64URL编码的HMAC值），无法验证签名真实性（需要密钥）。

问：JWT生成签名功能支持哪些算法？

答：本工具支持三种HMAC签名算法：1) HS256：使用SHA-256哈希算法，安全性高，适用于大多数场景，是默认推荐；2) HS384：使用SHA-384哈希算法，安全性更高，适用于对安全要求较高的场景；3) HS512：使用SHA-512哈希算法，安全性最高，但生成的签名较长。所有算法均使用对称密钥（Secret）进行签名，签名密钥应妥善保管，不要在不安全的环境中输入。

问：Base64URL编码和标准Base64有什么区别？

答：Base64URL和标准Base64的区别：1) 字符集：标准Base64使用A-Z、a-z、0-9、+、/，Base64URL使用A-Z、a-z、0-9、-、_；2) URL兼容性：Base64的+和/在URL中具有特殊含义，Base64URL将它们替换为-和_，可直接用于URL参数；3) 填充规则：标准Base64通常需要=填充，Base64URL通常省略尾部=填充；4) JWT使用：JWT规范强制使用Base64URL编码，Header和Payload必须使用URL安全的字符集。本工具的JWT生成和解析均使用Base64URL编码，符合JWT规范要求。
