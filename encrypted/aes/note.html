什么是 AES 加解密工具？

AES 加解密工具是一款基于 Web Crypto API 的在线对称加密工具，专为开发者、安全工程师以及需要快速保护敏感文本的用户设计。AES（Advanced Encryption Standard）是美国国家标准与技术研究院（NIST）于 2001 年确立的全球标准对称加密算法，具有安全性高、运算速度快、软硬件生态完善等特点。

本工具支持 AES-CBC、AES-CTR、AES-GCM 三种主流工作模式，支持 128/192/256 位三种密钥长度，并允许用户选择 Base64 或 Hex 作为输出格式。加密时工具会自动生成密码学安全的随机 IV/Nonce 并附加到密文前，解密时自动提取，极大简化了使用流程。

所有加密和解密运算均在浏览器本地完成，使用浏览器原生的 Web Crypto API 执行。密钥、明文、密文都不会上传到任何服务器，确保数据完全处于您的控制之下。

如何使用？

第一步：选择加密参数

根据需求选择加密模式（CBC/CTR/GCM）、密钥长度（推荐 256 位）和输出格式（Base64 更通用，Hex 更直观）。GCM 模式同时提供加密和认证功能，是最推荐的选择；CBC 模式通用性最好；CTR 模式适合高速流式场景。

第二步：设置密钥

密钥类型可选「文本密码」「Hex」或「Base64」。文本密码会通过 SHA-256 哈希自动派生为指定长度的密钥，便于记忆；Hex/Base64 密钥需要精确匹配所选密钥长度的字节数。点击「生成随机密钥」可快速获得高强度随机密钥。

第三步：执行加密或解密

加密时，在左侧输入明文，点击加密按钮，右侧即显示密文。解密时，将密文粘贴到左侧，确保密钥、模式、密钥长度和输出格式与加密时完全一致，点击解密按钮即可还原明文。

实战案例：保护配置文件中的数据库密码

某开发团队需要在版本控制中存储数据库连接字符串，但又不希望密码明文暴露。使用本工具选择 AES-256-GCM 模式，输入一个强密码作为密钥，对包含密码的配置片段进行加密，将得到的 Base64 密文存入仓库。部署时，运维人员使用相同密钥在本地解密即可读取原始配置。即使仓库泄露，攻击者也无法从密文中恢复密码。

注意事项：

  • AES 的安全性完全依赖密钥保密，请通过安全渠道传输和存储密钥
  • 不要对多个消息重复使用相同的密钥+IV/Nonce 组合
  • 如需同时保证机密性和完整性，优先选择 AES-GCM 模式
  • 生产环境建议使用密码学安全随机数生成 256 位密钥
  • 文本密码模式通过 SHA-256 派生密钥，与其他使用原始密钥的工具可能不兼容
  • 本工具专注于文本加解密，不适合直接加密大文件

常见问题

问：AES 是对称加密还是非对称加密？

答：AES 是对称加密算法，加密和解密使用同一个密钥。它的优势是速度快，适合加密大量数据；缺点是需要安全地分发密钥。密钥分发问题通常通过 RSA 等非对称算法或 Diffie-Hellman 密钥交换解决。

问：GCM 模式为什么比 CBC 更安全？

答：GCM 模式在加密的同时会生成一个认证标签（Authentication Tag），用于验证密文是否在传输过程中被篡改。CBC 模式只提供机密性，不提供完整性，攻击者可能在不知道密钥的情况下篡改密文。因此现代协议如 TLS 1.3 优先使用 GCM 等认证加密模式。

问：解密时 IV 从哪里获取？

答：本工具输出的密文格式为「IV/Nonce + 密文」的整体编码。加密时 IV 会自动生成并附加在密文前面，解密时会自动从密文前缀提取。因此解密时只需输入密文和密钥，无需单独提供 IV。

问：文本密码和 Hex/Base64 密钥有什么区别？

答：文本密码会先经过 SHA-256 哈希，再截断到所选密钥长度，因此任何长度的文本都能生成有效密钥。Hex/Base64 密钥则直接使用原始字节，必须精确等于所选密钥长度。Hex/Base64 模式更适合与其他加密工具或代码库进行精确兼容。

问：256 位密钥比 128 位慢很多吗？

答：在现代 CPU 和 Web Crypto API 的支持下，256 位 AES 与 128 位 AES 的性能差距非常小，通常可以忽略不计。因此除非有极端性能约束，否则建议直接使用 256 位密钥以获得最高安全级别。

安全最佳实践

  • 密钥保密：不要在代码仓库、前端配置或不安全渠道中泄露密钥或敏感凭证。
  • 本地优先：本工具所有计算在浏览器本地完成，处理完成后及时关闭页面，避免敏感信息驻留。
  • 结合多层防护：单一工具不足以构建完整安全体系，建议配合 TLS、访问控制、审计日志等措施。
  • 定期轮换：对长期使用的密钥、令牌或凭证建立轮换机制，降低泄露后的影响范围。
  • 选择合适算法：根据安全需求选择算法长度和模式，优先使用经过广泛验证的标准方案。
