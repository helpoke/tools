AES 对称加密：快速、安全、可逆的数据保护方案

为什么需要 AES 加解密

  • AES（Advanced Encryption Standard，高级加密标准）是目前全球最广泛使用的对称加密算法——速度快、安全性高、软硬件支持广泛。从 HTTPS、Wi-Fi WPA2/3、磁盘加密到密码管理器，AES 都是核心算法。
  • 本工具提供在线 AES 加密和解密功能，支持 CBC、CTR、GCM 三种常用模式，支持 128/192/256 位三种密钥长度。加密时自动生成随机 IV/Nonce 并附加到密文前，解密时自动提取，无需手动管理 IV。
  • 所有加密运算使用浏览器原生 Web Crypto API 执行——这是密码学安全的实现方式，性能接近系统级加密库。密钥和明文都不会上传到服务器，完全在本地完成。

加密模式说明

  • AES-CBC：密码块链接模式，每个明文块先与前一个密文块异或再加密。需要 16 字节 IV，简单可靠，但无法并行加密，且对 IV 随机性要求严格。
  • AES-CTR：计数器模式，将 AES 转换为流密码，可并行加解密。需要 16 字节初始计数器块，适合高速流式加密场景。
  • AES-GCM：伽罗瓦/计数器模式，同时提供加密和认证（完整性校验）。需要 12 字节 IV/Nonce，是现代网络通信（如 TLS 1.3）的首选模式。

核心功能

  • 双向加解密：输入明文点击加密得到密文，输入密文点击解密还原明文，一键切换。
  • 多模式支持：CBC、CTR、GCM 三种模式覆盖绝大多数开发和安全场景。
  • 灵活密钥输入：支持文本密码（自动派生）、Hex、Base64 三种密钥形式，并可一键生成随机密钥。
  • 双输出格式：结果可选 Base64 或 Hex 编码，方便在不同系统和协议间使用。
  • 本地处理：所有运算在浏览器本地完成，密钥、明文、密文均不上传服务器。

AES 使用指南

加密步骤

  • 选择模式：CBC 通用、CTR 高速流式、GCM 带认证。一般推荐 GCM。
  • 设置密钥：选择密钥长度（256 位最安全）和密钥类型。文本密码将自动通过 SHA-256 派生为指定长度密钥；Hex/Base64 需精确匹配密钥长度。
  • IV / Nonce：加密时留空，工具会自动生成随机 IV 并附加到密文前。高级用户也可以手动输入固定 IV（不推荐重复使用）。
  • 输入明文：在左侧输入框中输入需要加密的文本。
  • 点击加密：右侧输出框显示密文，格式为 Base64 或 Hex 编码的「IV + 密文」。
  • 复制结果：将密文和密钥安全地发送给接收方，两者缺一不可。

解密步骤

  • 输入密钥：使用与加密时完全相同的密钥、密钥长度和加密模式。
  • 输入密文：将密文粘贴到左侧输入框，工具会自动从密文前缀提取 IV/Nonce。
  • 点击解密：右侧输出框显示还原后的明文。

AES 基础知识

  • 密钥长度：128 位（16 字节）安全性足够；192 位（24 字节）更高；256 位（32 字节）目前最高安全级别， brute-force 需要天文数字级算力。
  • IV / Nonce：初始向量/随机数，确保相同明文加密后得到不同密文。CBC/CTR 使用 16 字节，GCM 推荐 12 字节。切勿重复使用同一密钥+IV 组合。
  • 填充：CBC 模式对不足块长的明文使用 PKCS#7 填充；CTR/GCM 本质上为流模式，无需填充。
  • 认证：只有 GCM 模式提供密文完整性校验，可检测篡改。CBC/CTR 不提供认证，需额外使用 HMAC。

注意事项

安全建议

  • 密钥保密：AES 的安全性完全依赖密钥保密。不要通过明文聊天、邮件或不安全通道传输密钥。
  • IV 不可预测：加密时必须使用密码学安全随机数生成 IV。本工具已自动处理，请勿手动输入固定值进行多次加密。
  • GCM 推荐：如需同时保证机密性和完整性，优先选择 AES-GCM。CBC/CTR 单独使用无法防篡改。
  • 密钥强度：生产环境建议使用 256 位密钥，并由密码学安全随机数生成，避免使用弱口令。

兼容性说明

  • 密文格式：本工具输出格式为「IV/Nonce + 密文」的连续字节，再整体进行 Base64 或 Hex 编码。IV 长度：CBC/CTR 为 16 字节，GCM 为 12 字节。
  • 文本密钥：选择「文本密码」时，工具先对密码做 SHA-256 哈希，再截断到所选密钥长度。此方式便于记忆，但与直接使用原始字节作为密钥的工具可能不兼容。
  • Hex/Base64 密钥：必须精确等于所选密钥长度的字节数。例如 256 位密钥需要 32 字节，即 64 个 Hex 字符或 44 个 Base64 字符（含填充）。

常见问题

  • Q: AES 是对称加密还是非对称加密？A: AES 是对称加密——加密和解密使用同一个密钥。适合加密大量数据；密钥分发问题可结合 RSA 等非对称算法解决。
  • Q: 解密失败怎么办？A: 检查密钥、密钥长度、加密模式、输出格式是否与加密时完全一致。任何一个参数不同都会导致解密失败。
  • Q: 256 位密钥比 128 位慢很多吗？A: 在现代 CPU 上差别很小。Web Crypto API 对三种密钥长度都有良好优化，一般无需为性能牺牲安全性。
  • Q: 可以加密文件吗？A: 当前版本专注于文本加解密。如需加密文件，可先将文件转为 Base64 再加密，解密后再转回文件。
