PBKDF2 是什么

PBKDF2（Password-Based Key Derivation Function 2）是一种标准的密码学密钥派生算法，由 RSA 实验室在 PKCS #5 v2.0 中提出，并被 RFC 2898 标准化。它的核心作用是将用户容易记忆的弱密码转换为高强度的密钥，供 AES 等加密算法使用。

PBKDF2 通过两个关键机制增强安全性：一是引入随机盐值（Salt），抵御彩虹表攻击并确保相同密码产生不同密钥；二是通过大量迭代（Iterations）重复伪随机函数运算，显著增加暴力破解的计算成本。即使攻击者截获了派生密钥，也很难反推出原始密码。

本工具基于浏览器原生 Web Crypto API 实现，严格遵循 PKCS #5/RFC 2898 标准，支持 SHA-1、SHA-256、SHA-384、SHA-512 四种哈希算法，可自定义盐值、迭代次数和输出密钥长度。所有计算在浏览器本地完成，密码和盐值不会上传到服务器。

PBKDF2 的工作原理

PBKDF2 的计算过程可以概括为：将密码和盐作为输入，通过多次迭代调用伪随机函数（PRF），最终输出指定长度的派生密钥。其公式为：

DK = PBKDF2(PRF, Password, Salt, c, dkLen)

其中，PRF 是伪随机函数（如 HMAC-SHA256），Password 是用户密码，Salt 是随机盐，c 是迭代次数，dkLen 是期望的输出密钥长度。迭代次数 c 越大，每次派生所需时间越长，暴力破解成本也越高。

五步完成密钥派生

第一步：输入密码

输入需要派生密钥的原始密码。密码的熵值直接影响最终密钥的安全性，建议使用包含大小写字母、数字和特殊符号的强密码，长度至少 12 位以上。

第二步：设置盐值

盐值是随机生成的数据，用于确保即使两个用户使用相同密码，派生出的密钥也不同。本工具支持自动生成密码学安全随机盐，也可以手动输入 Hex 或文本形式的盐。每个密码应使用不同的盐。

第三步：选择哈希算法

根据安全需求选择哈希算法。SHA-256 是推荐选择，兼顾安全性和速度；SHA-512 提供更高安全性但计算更慢；SHA-1 因安全性较弱，仅建议用于兼容旧系统。

第四步：配置迭代次数和密钥长度

一般推荐 100,000 次迭代和 256 位密钥长度，以平衡安全性和计算速度。迭代次数越高，暴力破解成本越高，但派生时间也越长。密钥长度根据用途选择，如 AES-256 需要 256 位。

第五步：派生密钥

点击派生按钮，工具会计算并输出 Hex 或 Base64 格式的派生密钥。请妥善保存算法、盐、迭代次数和密钥长度，解密或验证时需要完全相同的参数。

实战场景

加密密钥生成：将用户输入的密码转换为 AES 加密所需的 128/256 位密钥，无需用户直接管理复杂的二进制密钥。

密码验证存储：服务端不存储明文密码，而是存储 PBKDF2 派生值、盐和迭代次数。用户登录时重新计算并比对，有效防止数据库泄露后被破解。

文件加密：在本地加密文件时，使用 PBKDF2 从密码派生 AES-GCM 密钥，结合随机盐实现安全的文件加密。

跨平台密钥协商：在跨语言、跨平台系统中，使用标准 PBKDF2 参数确保各方派生出的密钥一致。

技术优势

PKCS #5 / RFC 2898 Web Crypto API SHA-1/256/384/512 随机盐生成 自定义迭代次数 Hex/Base64 输出 本地处理

注意事项：

  • 迭代次数推荐至少 100,000 次，安全要求越高可设置更大值
  • 每个密码应使用不同的随机盐，切勿全局复用
  • 解密或验证时需要完全相同的算法、盐、迭代次数和密钥长度
  • 本工具所有计算在浏览器本地完成，数据不上传服务器

实战案例：用户密码安全存储

某论坛在数据库泄露事件后发现，其早期使用 MD5 存储的用户密码被大量破解。为提升安全性，技术团队决定将所有密码存储方式迁移到 PBKDF2-HMAC-SHA256。

迁移方案：

  1. 用户注册或修改密码时，系统生成 16 字节（128 位）的密码学安全随机盐。
  2. 使用 PBKDF2-HMAC-SHA256，设置 100,000 次迭代，派生 256 位（32 字节）的密钥。
  3. 数据库中不再存储明文密码，而是存储盐、迭代次数和派生密钥的 Hex 字符串。
  4. 用户登录时，系统读取该用户的盐，用相同参数重新计算 PBKDF2，与数据库中存储的值比对。

效果：即使数据库再次泄露，攻击者也无法通过彩虹表快速破解密码。每次猜测一个密码都需要执行 10 万次 HMAC-SHA256 运算，大幅降低了暴力破解效率。相同密码因盐不同而产生完全不同的派生值，也有效防止了批量破解。

安全最佳实践

  • 盐值必须唯一：每个密码、每个文件、每个用户都应使用不同的随机盐。全局复用盐会让彩虹表攻击重新变得可行。
  • 迭代次数动态调整：随着硬件性能提升，应定期增加迭代次数。现代服务器通常可接受 100,000-600,000 次，移动端可根据响应时间适当降低。
  • 保存完整参数：盐、迭代次数、哈希算法和密钥长度都是派生密钥的必要输入。解密或验证时缺少任一参数都无法恢复密钥。
  • 盐不需要保密：盐值通常与派生密钥一起存储，其作用是防止预计算攻击，而非提供保密性。不要依赖盐来保护密码。
  • 密码强度仍然关键：PBKDF2 只能延缓破解速度，无法弥补弱密码。应强制用户设置足够长且复杂的密码。
  • 考虑更现代的替代方案：对于全新的系统设计，可以考虑 Argon2、scrypt 等内存困难型密钥派生函数，它们对 GPU 和专用硬件攻击有更强的抵抗能力。

FAQ 常见问题

问：PBKDF2 和直接哈希密码有什么区别？

答：直接哈希（如 SHA-256）计算速度极快，攻击者每秒可尝试数十亿次，容易被暴力破解。PBKDF2 通过大量迭代和盐值显著降低破解速度，更适合从密码派生密钥。

问：迭代次数越高越好吗？

答：迭代次数越高，暴力破解成本越高，但计算时间也越长。一般推荐 100,000-600,000 次之间，具体取决于应用场景对响应时间的要求。过高的迭代次数会影响用户体验。

问：盐值需要保密吗？

答：盐值不需要保密，通常与派生密钥一起存储。但它的作用是让相同密码产生不同结果，防止彩虹表攻击。每个密码应使用唯一盐值。

问：为什么相同密码和盐每次派生结果相同？

答：PBKDF2 是确定性算法，给定相同的密码、盐、迭代次数、哈希算法和密钥长度，始终会输出相同的派生密钥。这也是它能用于密码验证和密钥恢复的原因。

问：PBKDF2 输出应该选 Hex 还是 Base64？

答：Hex 格式便于阅读和调试，Base64 更紧凑。作为 AES 密钥使用时，两者都可以，关键是与加密工具的输入格式保持一致。存储到数据库时通常使用 Hex。
