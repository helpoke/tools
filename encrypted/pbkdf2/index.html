PBKDF2：从密码到安全密钥

为什么需要 PBKDF2

  • 用户设置的密码通常熵值较低，直接作为加密密钥容易被暴力破解。PBKDF2（Password-Based Key Derivation Function 2）通过大量迭代和盐值，将弱密码转换为高安全性的密钥。
  • 本工具使用浏览器原生 Web Crypto API 执行 PBKDF2，支持 SHA-1/SHA-256/SHA-384/SHA-512 哈希算法，可自定义迭代次数和输出密钥长度。

核心功能

  • 密钥派生：输入密码和盐，获得指定长度的派生密钥。
  • 随机盐生成：一键生成密码学安全随机盐，增强抗彩虹表能力。
  • 双格式输出：支持 Hex 和 Base64 编码。
  • 本地处理：所有计算在浏览器本地完成。

使用指南

使用步骤

  • 输入密码：即需要被派生的原始密码。
  • 设置盐：建议使用随机生成的唯一盐值，并妥善保存。
  • 迭代次数：推荐至少 100,000 次，安全要求越高可设置越大。
  • 密钥长度：根据用途选择，如 AES-256 需要 256 位（32 字节）。
  • 点击派生：获得最终密钥，可用于 AES 加密等场景。

安全建议

  • 盐值唯一：每个密码应使用不同的盐，切勿全局复用。
  • 迭代次数：迭代次数越高，暴力破解成本越高，但计算时间也越长。
  • 保存参数：解密或验证时需要完全相同的算法、盐、迭代次数和密钥长度。

典型应用场景

典型应用场景

  • 加密密钥生成：将用户输入的密码转换为 AES 加密所需的 128/256 位密钥，无需用户直接管理复杂的二进制密钥。
  • 密码验证存储：服务端不存储明文密码，而是存储 PBKDF2 派生值、盐和迭代次数。用户登录时重新计算并比对，有效防止数据库泄露后被破解。
  • 文件加密：在本地加密文件时，使用 PBKDF2 从密码派生 AES-GCM 密钥，结合随机盐实现安全的文件加密。
  • 跨平台密钥协商：在跨语言、跨平台系统中，使用标准 PBKDF2 参数确保各方从相同密码派生一致的密钥。

技术优势

  • 标准兼容：基于 PKCS #5/RFC 2898 标准，与 Python hashlib.pbkdf2_hmac、Node.js crypto.pbkdf2、Java SecretKeyFactory 等主流库完全兼容。
  • 参数可调：支持自定义哈希算法、迭代次数和密钥长度，灵活适配不同安全需求和性能约束。
  • 随机盐生成：一键生成密码学安全随机盐，有效防止彩虹表和预计算攻击。
  • 本地计算：基于 Web Crypto API，密码和盐值不会上传到服务器，适合处理敏感数据。

参数选择建议

一般推荐 SHA-256 + 100,000 次迭代 + 256 位密钥长度，兼顾安全性和计算速度。SHA-512 计算开销更大但安全性更高，适合高安全场景。SHA-1 因安全性较弱，仅用于兼容旧系统。迭代次数可根据设备性能和响应时间要求在 100,000 到 600,000 之间调整。

常见问题

  • Q: 迭代次数越高越好吗？A: 安全性越高，但计算也越慢。100,000 次是目前的最低推荐值，高安全场景可用 600,000 次。需要在安全性和响应速度之间平衡。
  • Q: PBKDF2 和 bcrypt 哪个好？A: 都是密码派生函数。bcrypt 内置内存消耗机制，更能抵御 GPU 攻击；PBKDF2 是 NIST 标准，兼容性更广。新系统建议考虑 bcrypt 或 Argon2。
  • Q: 盐值可以复用吗？A: 不建议。每个密码应使用独立的随机盐——盐值复用会降低安全性，使彩虹表攻击成为可能。
  • Q: PBKDF2 的结果能直接用作 AES 密钥吗？A: 可以。将密钥长度设为 256 位，派生结果可直接作为 AES-256 的密钥使用。这也是本工具 file-encrypt 模块的工作方式。
