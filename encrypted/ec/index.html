EC 椭圆曲线：更高效的非对称加密

为什么需要 EC

  • 椭圆曲线密码学（ECC）用更短的密钥实现与 RSA 相当的安全性。例如 P-256 约相当于 128 位安全级别，而 2048 位 RSA 也约相当于 112 位。ECC 密钥更短、计算更快、带宽占用更少。
  • 本工具使用 Web Crypto API 生成 ECDSA/ECDH 密钥对，支持 P-256/P-384/P-521 三条常用曲线，可导出 PEM、JWK 或 Raw 格式。

核心功能

  • 多曲线支持：P-256 通用、P-384 高安全、P-521 最高安全。
  • 多格式导出：PEM（最通用）、JWK（Web 应用）、Raw Hex（底层开发）。
  • 本地生成：私钥不离开浏览器，不上传服务器。

使用指南

使用步骤

  • 选择曲线：P-256 适合大多数场景，P-521 适合极高安全需求。
  • 选择格式：PEM 最通用，JWK 适合 JavaScript 应用。
  • 点击生成：立即获得公钥和私钥。
  • 保存私钥：私钥必须保密，建议安全存储。

安全建议

  • 私钥保密：私钥是 EC 密码学安全的根基，必须妥善保存，不可泄露或传输到不安全环境。
  • 曲线选择：P-256 已能满足大多数商业安全需求；P-384 和 P-521 适合需要更高安全冗余的场景。
  • 安全随机数：本工具使用浏览器内置 CSPRNG 生成私钥，确保不可预测性。

典型应用场景

典型应用场景

  • 数字签名（ECDSA）：使用私钥对数据或消息签名，任何人都可以用公钥验证签名来源和完整性。广泛应用于代码签名、文档签名和区块链交易。
  • 密钥交换（ECDH）：双方使用各自的 EC 密钥对协商出共享密钥，用于后续对称加密通信。TLS 1.3 大量使用了 ECDHE 进行前向安全密钥交换。
  • JWT 与 API 安全：ECDSA 签名在 JWT 中越来越流行，特别是 ES256 算法，因其更短的签名而减少传输开销。
  • 移动与物联网：ECC 的高性能和短密钥优势，使其特别适合资源受限的移动设备和 IoT 终端。

技术优势

  • 密钥更短：256 位 ECC 密钥可提供与 3072 位 RSA 相当的安全强度，显著降低存储和传输开销。
  • 性能更高：椭圆曲线运算比大整数 RSA 运算更快，尤其擅长签名和密钥协商。
  • 多格式导出：支持 PEM、JWK、Raw 三种格式，兼容不同平台和协议。
  • 本地生成：基于 Web Crypto API，私钥不会离开浏览器，适合处理敏感密钥。

曲线选择建议

P-256（secp256r1）是目前最广泛使用的曲线，兼容性和性能俱佳，适用于绝大多数 Web 和移动应用。P-384 提供更高的安全冗余，适合政府和金融机构。P-521 提供最高安全级别，但计算开销更大，适合对安全性要求极高且性能不是瓶颈的场景。

常见问题

  • Q: ECC 能替代 RSA 吗？A: 在安全性和性能上 ECC 已全面超越 RSA——256 位 ECC 相当于 3072 位 RSA。但在密钥管理生态和旧系统兼容性方面，RSA 仍有优势。新项目建议优先考虑 ECC。
  • Q: ECDSA 签名和 RSA 签名能互验吗？A: 不能。ECDSA 和 RSA 是完全不同的签名算法，密钥格式和签名格式都不兼容。验证方必须使用与签名方相同的算法。
  • Q: P-256 和 P-384 能混合使用吗？A: 不能直接混合。密钥交换和签名验证要求双方使用同一条曲线。如果服务端使用 P-256，客户端也必须使用 P-256。
  • Q: Raw 格式的公钥怎么用？A: Raw 格式导出的是纯公钥字节（Hex 编码），不包含曲线信息和格式包装。导入时需要手动指定曲线参数，适合底层开发场景。一般建议使用 PEM 或 JWK 格式。
