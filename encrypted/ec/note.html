EC 椭圆曲线密码学 是什么

椭圆曲线密码学（Elliptic Curve Cryptography，ECC）是一种基于椭圆曲线离散对数问题数学难题的非对称密码学。与 RSA 相比，ECC 可以用更短的密钥实现相当甚至更高的安全强度。例如，256 位的 ECC 密钥（P-256）约相当于 3072 位 RSA 密钥的安全级别。

更短的密钥意味着更低的存储开销、更快的计算速度和更少的网络传输量。这些优势使 ECC 特别适合移动设备、物联网终端、TLS 握手和高并发 API 场景。现代浏览器、操作系统和编程语言都已广泛支持 ECC。

本工具基于浏览器原生 Web Crypto API 生成 ECDSA/ECDH 密钥对，支持 NIST 标准化的 P-256、P-384、P-521 三条曲线。生成的密钥可导出为 PEM、JWK 或 Raw 格式，私钥不会离开浏览器，也不会上传到服务器。

ECDSA 与 ECDH 的区别

ECDSA（Elliptic Curve Digital Signature Algorithm）用于数字签名。签名者使用私钥对消息签名，验证者使用公钥验证签名。它提供消息完整性、来源认证和不可否认性。

ECDH（Elliptic Curve Diffie-Hellman）用于密钥交换。通信双方各自生成 EC 密钥对，交换公钥后，双方可以用自己的私钥和对方的公钥计算出一个相同的共享密钥。该密钥可用于后续的对称加密通信。

四步生成 EC 密钥对

第一步：选择曲线

根据安全需求选择合适的椭圆曲线。P-256 是最常用的曲线，兼容性和性能俱佳；P-384 适合高安全需求；P-521 提供最高安全级别但计算开销更大。

第二步：选择导出格式

PEM 格式最通用，兼容 OpenSSL 和大多数服务器；JWK（JSON Web Key）适合 JavaScript 应用和 JWT 场景；Raw Hex 适合底层协议开发和嵌入式系统。

第三步：点击生成

工具会使用浏览器内置的密码学安全随机数生成器生成私钥，并派生对应的公钥。整个过程在本地完成。

第四步：保存密钥

立即复制或下载公钥和私钥。私钥必须妥善保管，一旦泄露，所有基于该密钥的签名和加密都将失效。

曲线选择建议

P-256（secp256r1）

目前最广泛使用、兼容性最好的曲线。提供约 128 位安全级别，适用于绝大多数 Web、移动和 API 场景。

推荐用于大多数场景 兼容性好

P-384（secp384r1）

提供约 192 位安全级别，适合政府、金融和企业级应用。计算开销比 P-256 大，但安全冗余更高。

高安全性场景 计算开销适中

P-521（secp521r1）

提供约 256 位安全级别，是 NIST 推荐曲线中最高的。适合对长期安全性有极高要求的场景，但计算开销最大。

最高安全等级 计算开销较大

实战场景

数字签名（ECDSA）：使用私钥对数据或消息签名，任何人都可以用公钥验证签名来源和完整性。广泛应用于代码签名、文档签名和区块链交易。

密钥交换（ECDH）：双方使用各自的 EC 密钥对协商出共享密钥，用于后续对称加密通信。TLS 1.3 大量使用了 ECDHE 进行前向安全密钥交换。

JWT 与 API 安全：ECDSA 签名在 JWT 中越来越流行，特别是 ES256 算法，因其更短的签名而减少传输开销。

移动与物联网：ECC 的高性能和短密钥优势，使其特别适合资源受限的移动设备和 IoT 终端。

实战案例：TLS 1.3 握手与 ECDHE

当用户访问一个启用 TLS 1.3 的网站时，浏览器和服务器会使用 ECDHE（临时椭圆曲线 Diffie-Hellman）协商会话密钥。这个过程中，双方都生成临时的 EC 密钥对，交换公钥后计算共享密钥。

流程：

  1. 浏览器生成一个临时 EC 密钥对（通常使用 X25519 或 P-256）。
  2. 浏览器将公钥发送给服务器。
  3. 服务器也生成一个临时 EC 密钥对，并将自己的公钥返回给浏览器。
  4. 双方使用自己的临时私钥和对方的临时公钥，通过 ECDH 计算出一个相同的共享密钥。
  5. 该共享密钥用于后续通信的对称加密（如 AES-GCM）。

效果：由于每次会话都使用新的临时密钥对，即使长期私钥泄露，也无法解密之前的通信记录，这称为"前向安全"。ECC 的短密钥和快速计算使这一过程在高并发场景下非常高效。

安全最佳实践

  • 私钥保护：私钥是 ECC 安全的核心。应使用硬件安全模块（HSM）、密钥管理系统（KMS）或安全密钥库存储，避免明文保存在代码或配置文件中。
  • 随机数质量：私钥生成依赖高质量的随机数。本工具使用浏览器内置 CSPRNG，确保私钥不可预测。
  • 曲线兼容性：在与第三方系统交互前，确认对方支持的曲线和格式。P-256 兼容性最好，是首选。
  • 定期轮换：对于长期使用的签名密钥，建议定期轮换，并制定密钥撤销和更新流程。
  • 前向安全：在密钥交换场景中，使用临时（ephemeral）EC 密钥对，确保每次会话的密钥独立，实现前向安全。

FAQ 常见问题

问：EC 和 RSA 有什么区别？

答：EC 和 RSA 都是非对称密码学，但基于不同的数学难题。EC 基于椭圆曲线离散对数问题，可以用更短的密钥提供与 RSA 相当的安全性。EC 在签名和密钥交换方面通常更快，密钥和签名也更短。

问：P-256 安全吗？

答：P-256 提供约 128 位安全级别，是目前最广泛使用的 ECC 曲线之一，已被大量安全协议和系统验证。对于绝大多数商业应用，P-256 是安全且高效的选择。

问：PEM、JWK 和 Raw 格式有什么区别？

答：PEM 是 Base64 编码的文本格式，兼容 OpenSSL 和大多数服务器。JWK 是 JSON 格式，适合 Web 应用和 JWT。Raw 是原始字节数据，通常以 Hex 表示，适合底层开发和嵌入式系统。

问：私钥可以恢复吗？

答：不能。私钥是从随机数生成的，本工具不保存任何密钥。生成后请务必立即复制或下载并妥善保存，刷新页面或关闭工具后无法恢复。

问：ECDSA 签名和 HMAC 签名有什么区别？

答：HMAC 使用共享密钥，适合双方已预先约定密钥的场景。ECDSA 使用非对称密钥对，私钥签名、公钥验证，适合需要公开验证或多方验证的场景，也更容易实现不可否认性。
