RSA 密钥对生成：非对称加密的密钥管理工具

一、RSA 非对称加密原理

  • 对称加密（如 AES）使用同一个密钥加密和解密——密钥分发是最大难题。如何安全地将密钥传给对方？如果密钥在传输中被截获，整个加密体系就崩溃了。RSA 非对称加密用一对密钥解决这个问题——公钥加密，私钥解密。公钥可以公开分享，私钥永远保密。
  • 本工具使用 Web Crypto API（浏览器原生加密接口）生成 RSA 密钥对——支持 2048 位和 4096 位密钥长度，支持 PKCS#8（PEM 格式）和 SPKI（PEM 格式）导出。公钥用于加密，私钥用于解密——也可用于数字签名。
  • RSA 的安全性基于大数分解难题——两个大素数的乘积容易计算，但从乘积分解回素数极其困难。2048 位 RSA 的安全性相当于 112 位对称加密——以当前计算能力，分解 2048 位 RSA 密钥需要数十亿年。

二、密钥格式

  • PEM 格式：Base64 编码的密钥，用 -----BEGIN PUBLIC KEY----- 和 -----END PUBLIC KEY----- 包裹。最通用的格式——几乎所有编程语言和工具都支持。
  • DER 格式：二进制编码的密钥——PEM 就是 DER 的 Base64 编码版本。某些 Java 和 Windows API 直接使用 DER 格式。
  • SSH 格式：OpenSSH 使用的公钥格式——以 ssh-rsa 开头，一行包含算法、指数和模数。用于 SSH 登录认证。
  • JWK 格式：JSON Web Key——JSON 格式表示的密钥，包含 n（模数）和 e（指数）等参数。用于 JWT 和 Web 加密。

三、核心功能

  • Web Crypto API：使用浏览器原生加密接口生成密钥——性能接近系统级工具，安全性由浏览器引擎保证。
  • 多密钥长度：支持 2048 位（通用）和 4096 位（高安全）——密钥越长越安全，但生成和运算越慢。
  • 多格式导出：PEM 格式（通用）、复制文本或下载文件——方便在不同系统和语言间使用。
  • 纯前端生成：密钥对在浏览器中生成——私钥不离开你的设备，不上传到任何服务器。

RSA 密钥生成步骤

第一步：配置参数

  • 密钥长度：2048 位（通用，安全级别足够）或 4096 位（高安全，生成较慢）。一般场景 2048 位即可。
  • 输出格式：PEM 格式（Base64 文本，最通用）——适合直接粘贴到配置文件或代码中。

第二步：生成密钥

  • 点击生成：点击"生成密钥对"按钮——浏览器使用密码学安全随机数生成 RSA 密钥对。
  • 查看结果：公钥和私钥分别显示在两个区域——公钥可以分享，私钥必须保密。
  • 复制/下载：点击"复制"按钮复制密钥文本，或点击"下载"按钮保存为 .pem 文件。

第三步：使用密钥

  • 公钥用途：加密数据（对方用公钥加密，你用私钥解密）或验证签名（对方用私钥签名，你用公钥验证）。
  • 私钥用途：解密数据（你用私钥解密对方用公钥加密的数据）或创建签名（你用私钥签名，对方用公钥验证）。
  • 安全提醒：私钥一旦泄露，所有用对应公钥加密的数据都可能被解密——私钥必须安全存储（如加密的密钥库或硬件安全模块）。

注意事项

安全建议

  • 私钥保护：私钥绝不能通过网络传输或存储在不安全的位置——使用加密的密钥库（如 AWS KMS、HashiCorp Vault）或硬件安全模块（HSM）。
  • 密钥轮换：建议每 1-2 年更换一次 RSA 密钥对——降低长期密钥被破解的风险。
  • 密钥长度：2048 位 RSA 的安全级别约等于 112 位 AES——目前足够安全。4096 位约等于 140 位 AES——适合长期安全需求。

密钥长度选择

  • 2048 位：通用首选——生成速度快（1-3 秒），安全级别足够大多数场景。
  • 4096 位：高安全需求——生成速度慢（5-15 秒），适合保护长期敏感数据。
  • 1024 位：已不安全——2010 年后不建议使用。某些旧系统可能仍使用 1024 位。

常见问题

  • Q: RSA 能加密大文件吗？A: RSA 只能加密小于密钥长度的数据——2048 位 RSA 最多加密 245 字节。大文件应使用混合加密（AES 加密数据 + RSA 加密 AES 密钥）。
  • Q: 公钥和私钥能互换吗？A: 技术上 RSA 的公钥和私钥可以互换使用——但语义上不应互换。公钥加密的数据只有私钥能解密，反之亦然。
  • Q: 生成的密钥安全吗？A: 使用 Web Crypto API——浏览器底层的密码学安全随机数生成器。与 OpenSSL 等系统级工具的安全级别相同。
  • Q: 生成的 SSH 格式为什么不能直接用于 GitHub？A: 选择 SSH 格式时，公钥为 ssh-rsa 单行格式，私钥为 -----BEGIN OPENSSH PRIVATE KEY----- 格式。GitHub 要求 RSA 密钥至少 3072 位，请在此选择 3072 或 4096 位；2048 位及以下会被 GitHub 拒绝。将公钥内容粘贴到 GitHub 的 SSH Keys 页面，私钥保存到本地 ~/.ssh/id_rsa 即可使用。
